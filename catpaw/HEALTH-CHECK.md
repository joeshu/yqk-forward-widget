# CatPaw 健康检查与证据绑定（0.7.0）

当前代码保留81个源实现，默认展示53个；28个停用记录保留，不因一次检查自动改变启停状态。

## 当前只读边界

运行 `npm --prefix catpaw run build`，再运行 `node catpaw/live.cjs`。检查仅执行 home、category、detail、search，不执行 init、play、proxy、广告奖励或媒体请求。SDK及参考请求层会在请求发送前拦截登录、注册、游客会话创建、奖励、充值和购买路径；重定向逐跳检查。被边界阻止的检查标为 NOT_RUN，不判为源已损坏。

每个检查动作携带独立取消信号；超时或动作结束会取消该动作仍在进行的请求。请求作用域通过服务内部一次性标识绑定，避免 Fastify inject 的异步调用丢失作用域。它不是对外的健康检查开关。检查使用独立内存存储，不导入个人Cookie，不写正常浏览诊断记录。

报告写入 `catpaw/reports/runtime/提交-包哈希-时间.json`，不覆盖旧报告。报告包括 mode、gitCommit、sourceFingerprint、bundleSha256、展示源数量和完整来源集合。只有包哈希、源码指纹、展示数量和来源集合全部一致，且采用 catalogue-read-only 模式，才判为 CURRENT。

发布的 info.json 显示当前构建身份、81/53/28数量和健康证据状态；source-layout.json 提供每个源的展示策略。source-layout.json 的 catalogueStatus=NOT_RUN 表示展示结构检查，不是在线目录或播放验收。构建与测试通过也不等于手机实播通过。

## miraPlay 诊断与布局

所有源增加「诊断状态」。它没有影片卡片；状态、时间、操作、耗时及错误直接显示在筛选行。先复现错误，再重新进入该源以刷新 home 筛选信息，然后进入诊断状态。记录是历史记录，不是实时在线探测。`GET /diagnostics/:key` 也可读取脱敏记录及运行版本。

12个快照源的播放参数移到「播放设置」；按源保存，后续打开的影片采用新设置，已经打开的影片保留其原来的线路参数。浏览分类只显示浏览筛选。分类标识和原站内容保持原协议；分类、筛选和值去重，简介徽标缩短，详情正文保留。无推荐列表时只读取首个真实内容分类第一页，不遍历所有分类；次元城及星芽修复首页 list 嵌套分页对象的问题。

## 既有 TLS 策略

本轮未扩大TLS例外。runtime.js仍只对 yz250907.hzkeka49.com、ai.baipiaozhe.com、www.4kvms.org 使用既有精确主机例外，其余主机严格验证。CATPAW_STRICT_TLS=1可恢复全严格模式。参考源请求层仍保持其既有严格TLS策略；此处不将例外描述为证书修复或安全保证。
