# CatPaw 81 源在线健康检查（2026-10-13）

## 可复现方式

在仓库根执行：

```sh
npm --prefix catpaw test
npm --prefix catpaw run build
node catpaw/live.cjs
```

`catpaw/health-check.cjs` 逐个对 `/home`、第一页 `/category` 发起真实只读请求；有可识别列表项时再抽样 `/detail`、`/play`（另用该标题试一次 `/search`）。每个路由单独捕获异常，限制单次等待时间，异常数据不会中止后续来源。报告写入 `catpaw/validation.json`，含时间、构建 SHA-256、81 项源结果、逐项错误与限制说明。`passed` 仅表示首页和第一页分类列表有效，不代表每项详情、搜索、媒体或整站均可用；播放只确认返回 URL，不下载/解码媒体。对结果复测时会覆盖该报告文件。

检查不使用用户凭据，不登录、不绕过验证码、广告奖励、付费或其他安全门槛，不发送会改变账号/生产配置的请求。报告的失败不等同于源站停服：HTTP 403/502、拒绝、空分类、错误结构及传输/TLS 问题分别记录，不据此批量停用默认源。

## 本轮根因与证据

本机 Node v22.23.2 的 `tls.rootCertificates` 有 145 项，`NODE_EXTRA_CA_CERTS` 和代理环境变量均未配置；运行严格证书验证，未使用 `rejectUnauthorized:false` 或 `-k`。独立 Node TLS 握手显示，多个历史报错主机（如 `yz250907.hzkeka49.com`、`ai.baipiaozhe.com`、`www.4kvms.org`）实际返回的站点证书由 `Quantumult X CA 238C4977` 签发，而其签发根不在该 Node 根证书集合中，因此抛 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`。这三个不同注册域名返回同一个 Quantumult X 拦截 CA，指向当前出口/设备的 HTTPS MITM 证书信任配置，而非代码中八个来源各自的共同坏代码；`m.yqk3hxe.com` 同时返回正常 Let's Encrypt 证书，证明并非所有目标都同样经过该证书链。`www.auete.com` 另单独返回已过期证书（到期 2026-10-07），该端点错误须与 MITM 链错误区别对待。测试日期与证书时间见本机系统时间。

一起看的 6 个回退 API 域名在 `yqk.js` 中作为显式备用地址，此外运行时先读公开 `baseUrlList.js` 配置；这不是可安全替换的同域拼写。它们的当前 API 业务请求受同一未受信 Quantumult X 链影响，不能因此判定服务端 6 个域名全坏，也不应只凭旧探针停用一起看。其独立站点 `m.yqk3hxe.com` 首页在 Node 请求中 HTTP 200；本轮 CatPaw 实际 `/home` 可用，但 `/category` 返回 HTTP 502，因此当前出口下列表未验成，原因仍需由可信直连网络复测。没有修改回退域名或证书验证策略。

## 本轮 81 源结果摘要

`catpaw/validation.json` 对配置中的全部 81 个源均生成一条结果，0 项遗漏：本次环境中 38 个源通过首页及首个分类列表（`passed`）；43 个源的核心列表检查未通过。其中部分是 HTTP 502、空类目或业务返回结构异常，部分接口受本机代理/TLS链影响；此统计不能解读为 43 个源确定损坏。成功列表中 37 个源完成详情抽样，33 个源返回播放 URL（3 项播放请求失败、1 项没有剧集；精确逐项状态以 JSON 为准）；详情、搜索、播放上的单项失败独立保留在对应 `checks` 中，不会再中断其他来源。没有下载视频流。真实列表与详情取样覆盖远超原先的 12 个快照源；完整参考源失败项尚不能区分源端过时、区域/WAF、代理证书和业务参数限制，需要在不经 MITM 的可信网络逐项复核。

## 默认启停与共用域名

本轮仅暂时禁用 10 个 AppV7 动态秒播源（师兄、粉猪、咸鱼、追剧、柚子、柠檬、太奇、零七、柿子、黄人）：10 个各自的真实只读 `init/home` 流程均到同一动态 AppV7 配置加载流程，线上 `crypto.php?action=config&key=<source-key>` 查询返回 HTTP 404，因缺 `host` 配置而无法获得首页；这是配置服务对这些明确业务 key 的不存在响应，不是前述 Quantumult X TLS 错误。保留适配实现，在 `catpaw/reference/metadata.json` 记录停用理由，恢复服务后将其 `enabled` 置回 `true` 即可恢复默认展示。不将其他 32 个失败列表或所有 81 源一概视为坏源；其失败是 TLS/网络限制、404 子接口、空类目或接口/解析行为异常，证据不足以停用。

其他来源没有禁用：当前没有排除本机网络问题后可靠确认其业务失败。所有源的 routes 和代码仍保留；只是上面 10 个从默认 `/config` 列表隐藏。共享域名静态检查确认：金牌影院与追影猫快照使用同一个 `m.vv3nwjk.com`；多源共用站点会发生重叠，但适配器按 source key 隔离 ID、缓存、请求/播放器上下文，没有依据将域名相同解释为相互冲突。可可影视快照另用 `www.kkys20.com`，与金牌/追影猫并不共用该站点；没有全局重写共享请求头。
