# 五份参考猫源接入（0.8.0）

本次保留原81个实现，新增102个内容源实现，共183个登记入口，默认启用155个，既有28个停用项保持原状。新增实现保留供应方标签；同站不同实现作为独立选项供手机比较。牛二已有69个内容源适配复用原实现，额外接入点播直播；潇洒接入70个显式/动态内容源；豆儿11个、Y佬11个、L佬9个。

`inventory.json`逐项记录新增、既有复用及排除原因。按既有要求排除网盘、盘搜、磁力转网盘，以及配置/推送/本地插件管理项；需要自备Emby、Alist、WebDAV服务的模板不冒充可用片库。原包中由用户配置才会产生的外部插件/服务不是固定预设源，未构造虚假账号或虚假片单。

五份原包均通过MD5校验，原始散列与公开下载地址见`provenance.json`。豆儿的下载需要认证，下载凭据未进入仓库和运行包。仅保存所选内容处理器的依赖闭包，排除原服务器、后台和自动启动代码；保留原始捆绑许可证。压缩组件在首次使用某个供应方时才解码并校验SHA-256，不在导入订阅时并发请求网站或启动第二个端口。

兼容两种原源接口：对象方法式与Fastify插件式。标准首页/分类/搜索/详情/播放和各源额外的HLS、DASH、图片、分片、播放代理路由均保留。原源代理前缀转换为独立的供应方命名空间；HTTP请求及原请求/响应拦截器通过统一传输层执行，只读检查不执行初始化、播放、代理或客户端桥接动作。Node缓存和本机持久资料按供应方隔离；资料修改使用可恢复保存队列。外部共享Cookie请求仍被禁止；组件中的非空Cookie、密码及固定账号标识默认值已清空。

原源需要用户Cookie、授权、播放桥接或自备直播列表的条件继续生效。`index.config.js`可用`importedSources`配置对应供应方的源参数；不导入别人的账号状态。未把原后台网页一并搬入。

注册审计见`registration.json`：102个新增源均包含完整五项核心处理器，整个注册过程网络被阻止。离线回归覆盖195集、HTTP失败诊断、源端资料并发保存、保存失败恢复及只读播放边界。`live-sample.json`是有限的分类抽查，不是全源健康证明；其中记录被测构建散列，后续重新构建时应按历史记录理解。手机实际点播一律未验证。

## 维护组件

组件位于`packs/*.gz.b64`，不是运行时远程加载。解码示例：

```js
const fs = require('node:fs');
const zlib = require('node:zlib');
const text = zlib.gunzipSync(Buffer.from(fs.readFileSync('packs/douer.gz.b64', 'utf8').trim(), 'base64')).toString('utf8');
```

提取工具见`tools/`。维护时将下载和格式化后的原包放在独立输入目录，设置`CATPAW_IMPORT_INPUT_DIR`；`catalogue.cjs`生成静态清单，`extract.cjs <provider>`按`KEYS`和输入目录的`<provider>.extra.json`提取依赖闭包。动态选择规则见`tools/selection.json`；加载元数据后需核对真实`meta.key`、审查依赖及清除账号默认值，再更新压缩组件和散列。不要仅用元数据名称代替原处理器，也不要重新执行原`start()`或后台注册函数。

发布和客户端地址保持不变：`https://joeshu.github.io/yqk-forward-widget/catpaw/index.js.md5`。同行`import-report.json`公开逐源对照表，`source-layout.json`记录所有入口的展示策略，`info.json`标记实际构建身份。
