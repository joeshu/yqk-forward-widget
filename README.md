## 0.8.0：线路、分类与更新优先

- **线路**：默认自动检查最多六条 HLS 候选，两条并发，返回最多三条检查通过的线路；拒绝 403/404、伪装成清单的 HTML 和空清单。主清单优先尝试高分辨率子清单，失败再试一个较低变体，单条最多五次清单读取、三层嵌套；返回已检查的实际子清单地址。不会下载视频分片、密钥或完整 MP4。
- **线路偏好**：同片同集优先试最近十分钟成功的源，只保存源 ID 与时间，最多三十条提示，不缓存临时播放 URL。相同分集并发检查合并；遇到 429 不再发起下一批。保留「全部直连」手动模式；自动模式只检查有限候选，不等于全站所有线路验收。
- **分类**：新增电影、电视剧、动漫、综艺、短剧、纪录片六个独立栏目，支持对应类型、地区、今年/去年/前年和更新/热度排序。请求使用真实原站参数，并核对返回分类、类型、地区与年份，排除不符合所选条件的条目；因此筛选后部分页可能少于二十项。
- **推荐与榜单**：首页覆盖更多原站推荐，同时提供国产、美剧、韩剧、日剧、动画及电影片单选择；新增今日/本周/本月热播榜。
- **尽量最新**：新增「最新资源更新」与「当年新片新剧」，年份随北京时间自动滚动；最新栏目排除未来年份异常条目，卡片显示北京时间的资源更新时间。更新栏目、推荐与分类缓存缩短为六十秒。最新入库/资源更新可能包含旧片补录，不能等同于首映日期；每页按返回更新时间排序，跨页仍由原站快照决定，不宣称全站严格时间排序或实时同步。
- 当前真实验证见 `souju-validation.json`，0.1.0 历史证据保留为 `souju-validation-0.1.0.json`；运行时和版本化脚本必须与证据 SHA-256 一致。

## 搜剧AI

目标站点：https://ai.baipiaozhe.com

- 首页推荐、电影/电视剧/动漫/综艺/短剧/纪录片分类与分页、片名搜索。
- 原始海报、年份、类型与更新状态；电视剧按真实分集显示，超过 100 集通过「后续分集」继续浏览；其他季独立显示。
- 使用原站匿名访客会话和公开前端请求签名；会话在客户端存储中保存，失效只刷新一次。没有账号登录或账号凭据。
- 空搜索不请求网站；请求限流、签名失效或会话获取失败明确报错。
- 播放时核验影片与分集身份，并重新获取原站返回的访客直连线路，并按所选模式检查清单。解析票据、账号等级受限线路不纳入本版；不调用可能消耗站点额度的解析接口。

- 真实接口与媒体清单样本验证见 `souju-validation.json`；这些证据不保证全部影片、线路或视频分片可播放，也不包含原站 AI 聊天功能。

## 修复点

1. 旧版只试前三个 API 域名，这三个失效；完整列表后面的多个域名实际上正常。优先使用成功域名，保留完整官方地址列表用于故障转移。
2. 清晰度字段是 vodResolution，不是 res。
3. 分页 nextVal 是数组；保留原类型参与请求和签名，用值比较检查游标是否推进。
4. 存储兼容官方异步字符串接口，同时支持客户端同步返回；序列化游标和缓存。存储不可用时保留当前执行的内存缓存。
5. 官方首页真实结构是 vodTopicList[].vodList，增加首页精选并去重。
6. 分类编号来自真实首页响应：电影 2、电视剧 3、动漫 8、综艺 10，可直接选择。
7. 分集只展示当前线路，其他线路使用 childItems 展示；点击线路后 loadDetail 选择该线路的分集，避免多个源混成几百集。
8. 播放地址临时生成，不缓存签名播放 URL；只请求 canPlay=true 的访客资源。

### 0.3.0 新增优化

- 相同请求合并，同一查询的分页串行推进，避免并发翻页覆盖游标；失败后不会锁死队列。
- 缓存域名全部失效时重新读取官方地址列表，新增域名可立即接管；损坏、过期或未来时间的缓存会重建。
- 详情元数据缓存 60 秒，减少线路切换及播放前的重复请求；不缓存临时播放地址。
- 播放前核对分集确实属于当前影片，防止错配；单个清晰度失败不会丢掉其他可用资源，默认清晰度优先。
- 并发签名共享同一设备标识，避免初始化竞争。

### 0.4.0 新增优化

- 先校验并转换完整列表，再提交分页状态，失败不污染已保存游标。
- 中间页游标改变或提前结束时清理后续游标，并检测循环游标。
- 不同接口并发调用共享 API 域名发现，减少冷启动重复请求。
- 新增 deploy.cjs 发布工具，从真实 HTTPS 域名生成版本化 JS、正式 .fwd 和托管配置。
- 详细部署及更新回滚说明见 DEPLOY.md；仅静态托管，不需要后台 Node 服务。

### 0.5.0 易用性与稳定性

- 热搜提供综合/电影/电视剧/动漫/综艺的中文选择；普通分类无需填写子分类编号，仍保留旧参数处理逻辑。
- 搜索支持粘贴片名，清除不可见分隔符并合并多余空白；输入提示提供片名示例。
- 线路标明“当前”及集数；过滤空线路、损坏分集及重复分集，缺失分集标题提供可读名称。
- 分集未匹配时只额外刷新一次详情再核对，避免缓存内没有新集时直接误报下架；仍拒绝其他影片的分集。
- 当前会话优先读最新内存值，存储写入失败后不会马上读回旧磁盘数据。内存中的详情/分页缓存合计最多 80 项，不影响设备标识；持久存储未实现全量自动清理。
- 清晰度去重且兼容空条目；HTTP 429 立即提示稍后重试，不继续切换 API 域名增加请求。
- 连接失败提示汇总重复原因；不向普通用户要求修改源代码中的接口配置。
- 对后缀为 .m3u8 的地址检查清单状态和 #EXTM3U 内容，拒绝 HTTP 错误及伪装成成功的 HTML。清单可读取仍不等于全部分片可播放。
- 默认线路失败时最多尝试四条同片同集线路；电影仅匹配单集“正片/HD”等正片标签，电视剧按实际分集名匹配（支持第01集/第1集）。不按分集列表位置猜测集数，不跨影片切换；播放资源标明实际使用的线路。
- 限流立即中止清晰度和线路重试；MP4、无 .m3u8 后缀的地址不做媒体下载探测，HLS 分片也不会被运行时预下载。

- package.json / package-lock.json：开发测试依赖与锁定版本。

## 开发复测

需要 Node >=24、Python 3；默认通过 Python 标准库处理开发环境的网络代理，官方 WidgetAdaptor 负责 HTTP 返回格式与存储语义。

    npm ci --ignore-scripts
    npm test
    npm run test:live

单独复测新分类、专题分页、Netflix/韩剧和访客画质：`CATALOG_ONLY=1 node live-test.cjs`。
单独复测五个热搜选项：`HOT_ONLY=1 node live-test.cjs`。
单独复测电影自动切换、首个 HLS 分片及两秒本地解码：`MEDIA_ONLY=1 node live-test.cjs`（额外需要 ffprobe/ffmpeg）。
这两个命令分别写入 hot-validation.json 和 media-validation.json；开发传输工具保留二进制原始字节，并限制单次响应为 16 MiB，手机运行脚本不依赖此工具。

真实验证会发出只读查询请求，不模拟成功响应。SDK 输出经过官方 Zod schema 校验。由于 Node 不对 node_modules 中的 TypeScript 做类型剥离，测试工具仅移除 schema 中的两个 ZodTypeAny 类型注解后加载临时副本。

## 已知边界

- 验证是当前样本的真实网络结果，不是对全部内容的穷尽验证。
- 测试拿到的清晰度名称“标清”不能用来判断视频实际像素尺寸，视频编码信息以分片识别为准。
- API 故障转移依赖客户端对网络请求的超时处理；全部域名故障时会报错，不返回伪造内容。
- 自动切换默认最多八条线路，可选四／八／十二条，每条最多处理四个不同清晰度。清单检查会增加少量请求，慢网络时等待可能较长，具体超时由客户端控制；不保证任意影片都能找到可用线路。
- 分集名称缺失或无法匹配时不会盲目按顺序切换其他线路，请手动选择。明确不同的电视剧集数，即使每条线路只有一集，也不会互相替代。
- 播放根详情链接默认选第一条线路的第一分集；播放指定集数应从分集列表进入。
- API 目前不需要账号登录；本版未实现登录。某些资源或更高清晰度若需账号权限，按站点提示处理。
- 首页可按专题选择；选择“全部首页精选”时仍展开为去重片单。
