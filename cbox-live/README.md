# cbox-live v1.5.4 单文件：APTV 推荐版

Python 文件既可在 APTV 内置 Python 服务中运行，也可放在电脑、NAS 或服务器上运行。先启动脚本服务，再用它提供的 HTTP 地址加载频道；raw Python 下载地址不是频道订阅地址。



## v1.5.4：央视频清单中转、分片直连

默认央视频采用 `relay`：Python 获取并下发直播清单，公开媒体分片使用官方绝对地址，由 APTV 自己连接 CDN 下载；嵌套清单仍通过本地代理读取和重写。服务不再为了普通播放先下载这些分片，也不会通过“试拉分片”选择 CDN。央视频取票仍为纯 Python，APTV 内置运行无需 Node。

这补齐上游项目 `extractors/yangshipin/index.js` 的关键处理方向。上游记录过服务端逐片代理被拒、播放器直连可播的情况；这不是对所有 403 的通用修复，实际手机播放仍需验证。

- 央视频票据默认缓存 300 秒；清单独立刷新，同频道两秒内共享，避免把直播清单缓存五分钟。清单失败仍可尝试官方备用入口和提前换票。
- 实例级新频道取票预算为容量 8、每 60 秒补充 8 个；近期仍在观看的频道刷新不消耗冷启动预算。大量切台或批量检测可能收到明确的暂缓提示，不删除频道。
- 已知频道的 HEAD 请求仅本地确认路由存在，不代表已验证可播放，不向官方取票。
- 已有最近有效清单时，刷新等待最多约 3.5 秒；超时先返回旧清单，同一个后台任务继续刷新，后续轮询可及时取得结果。旧清单最多使用 30 秒，不无限维持过期内容。
- 上游 403 后短暂冷却，版权停播提示冷却约三分钟，避免播放器反复重试接口。目录仍为 85 个不同频道，原 61 台保留；不是 85 台均已逐台验证可播。

**同一手机的 APTV 内运行：**停止旧服务、替换脚本、重新启动，并刷新订阅：

```text
http://127.0.0.1:8767/aptv.m3u
```

如需对比旧的央视频分片代理路径，可启动 `python cbox-live.py 8767 --ysp-media proxy`；默认无需添加参数。`--ysp-ticket-ttl 300` 可调整央视频取票缓存；原 `--resolve-ttl` 继续用于原有模式。批量检测也受取票保护限制，不建议反复运行全台检测或刷新预览图。

诊断地址仍为 `http://127.0.0.1:8767/diagnostics.json`，其中央视频 `media_delivery` 应为 `relay`。直连后 Python 无法看到 APTV 与 CDN 之间的分片 HTTP 错误；若仍不能播放，请提供频道名称、APTV 播放器日志、服务日志，以及手机是否开启代理。`--direct` 只控制 Python 请求，不能控制 APTV 自己的网络路径。

验证：126 项回归测试通过，另有 13 项最新专项测试通过（其中 12 项与回归重叠）；包括直连媒体地址、嵌套清单、并发刷新、取票预算、已知频道 HEAD、旧清单过期和真实超时后恢复。无 Node 测试进程使用旧 `/cctv1.m3u8` 入口持续读取清单，并直接向官方 CDN 下载分片，结果见 `validation-v1.5.4.json`。测试环境不等同于用户 iOS；原 App UDRM 仍未实现。

## v1.5.3：减少重复回源，补齐 403 诊断

最新手机日志中服务已启动并持续运行，主要失败为 62 次上游 HTTP 403。旧日志没有记录被拒绝的频道、域名和请求阶段，因此尚不能确认手机端的具体原因，也不能宣布 403 已解决。

本版合并同一分片的并发请求；央视频 TS 的 Range 探测与完整读取共享一次完整回源，并由本地返回所需范围。失败请求短暂退避，避免播放器立即重复请求同一个失败地址。官方直播清单共享两秒；对于支持的普通 TS 清单，同一频道、同一分片保持对外地址稳定，实际读取使用官方清单最新提供的地址。加密、字节范围、时间线中断等复杂清单不应用这一地址稳定处理。

日志增加频道、上游域名及 API/清单/媒体阶段，避免只剩“HTTP 403”；缺少 Node 时跳过无法使用的网页备用来源，仍保留原 61 台目录。新增诊断导出：

```text
http://127.0.0.1:8767/diagnostics.json
```

诊断含来源状态与最近媒体错误，不输出签名参数、抓包模板或代理凭据。若更新后仍然失败，请在尝试播放后保存新的服务日志和诊断 JSON，并说明频道名称、手机是否开启代理。JSON 中的代理环境变量标记不能判断手机 VPN 或抓包软件是否启用。

验证：114 项自动测试通过；无 Node 的测试进程中，CCTV1 清单轮询 7 次、持续约 63 秒，获取 13 个不同分片，首次 Range 请求返回 206，拼接媒体 FFmpeg 解码零错误。这些是测试环境结果，未在用户 iOS 上验证，也不代表全部 85 条目录均可播放。原 App UDRM 仍未实现。

## v1.5.2：APTV 内置 Python 兼容

新日志确认环境为 APTV.app 内置 Python 3.14。v1.5.1 已修复启动退出，但旧入口仍可能把播放器引向依赖 Node 的网页 CDRM；同时，播放器取消请求或切台时的 TCP 连接重置发生在 `do_GET` 之外，导致大量错误堆栈。

本版在默认网页模式未安装 Node、且央视频来源启用时，将未加模式前缀的 `/all.m3u`、`/playlist.m3u` 和对应节目单自动改为 APTV 同台多源目录；旧的 `/cctv1.m3u8` 等频道 URL 也使用同台备用选择。无需安装 Node，原有 61 台仍在目录中。

显式 `/web/` 仍代表网页协议；没有 CDRM 内核时返回清晰的 HTTP 503，不先下发无法处理的加密媒体。旧代理 URL 的相同能力提示一分钟最多记录一次。已在完整 HTTP 请求生命周期中处理播放器主动断连，避免 `ConnectionResetError` 从读取下一条 keep-alive 请求时逃逸；真实服务错误继续报告。

**直接在同一手机的 APTV 内运行脚本时，使用：**

```text
http://127.0.0.1:8767/aptv.m3u
```

节目单为 `http://127.0.0.1:8767/aptv-epg.xml.gz`。只有脚本部署在另一台设备时，才将 `127.0.0.1` 换成那台设备的局域网 IP。

更新步骤：停止旧服务，替换 Python 文件，重新启动，再刷新现有频道订阅。若原订阅明确使用 `/web/all.m3u`，请改为上面的推荐入口。

验证：104 项回归测试通过，包含真实 TCP RST、旧默认订阅、旧频道 URL、缺少内核时的提前拒绝。无 Node 子进程中，通过默认/旧频道 URL 实际取流，CCTV1、CCTV13、湖南卫视、宁夏卫视各连续三片均 FFmpeg 零错误。未直接操作用户的 iOS 设备。

## v1.5.1 托管运行修复

针对“显示监听地址后立即退出，退出码 1”的日志，已在旧版复现底层异常：`ValueError: signal only works in main thread of the main interpreter`。

本版在非主线程运行时跳过进程信号注册，继续提供 HTTP 服务；主线程但运行平台不支持信号注册时也可继续服务。退出时只恢复本进程成功注册的信号，并确保关闭服务端端口。

缓存目录不可访问时明确切换为内存模式；避免为同一来源重复初始化缓存。缓存格式损坏时重新读取官方节目单，不因此阻止服务启动。程序默认将普通运行日志写入 stdout，并标注 INFO/WARNING，减少托管器把正常输出统称 error 的情况；真实文件或端口异常显示具体类型与原因。

已在“非主线程 + 缓存不可写 + 无 Node”的组合环境中，验证 HTTP 订阅持续可用、推荐目录 85 条、原 App 目录 61 条，以及关闭后端口可重新绑定。原有播放源和订阅 URL 不变。

## 启动

需要 Python 3.10+。央视频签名已移植为 Python 标准库实现，无需 Node、pip 包、账号 Cookie 或额外 JS 文件。

```bash
python cbox-live.py 8767
```

Node.js 18+ 是原网页 CDRM 模式的可选依赖；未安装时服务仍能启动、央视频仍可播放，网页 CDRM 来源会明确报告内核不可用。FFmpeg 仅用于可选视频诊断。

## 手机 APTV 填写

推荐订阅：

```text
http://运行设备的局域网IP:8767/aptv.m3u
```

配套节目单：

```text
http://运行设备的局域网IP:8767/aptv-epg.xml.gz
```

例如服务器 IP 为 `192.168.1.20`，订阅填 `http://192.168.1.20:8767/aptv.m3u`。节目单地址已经包含在订阅头内，APTV 未自动识别时再手动填写。脚本在另一台设备运行时，手机与服务器需网络互通；在同一手机的 APTV 内运行时，则填写 `127.0.0.1`。

## v1.5 的主要改动

- **APTV 专用目录 85 条**：原 61 台全部保留，再增加 24 个不同频道条目；同台不同源合并到同一频道，不在推荐列表重复出现。
- **同台备用选择**：优先央视频，再尝试同频道地方官方源及原网页 CDRM。正在使用的来源持续被轮询时保持选择；清单或媒体失败后可在下一次清单请求选择同台备用源。失败来源短暂退避，避免连续请求故障接口。
- **纯 Python 签名**：与上游 JavaScript 的固定随机输入样例逐字节一致，且通过实际接口、视频分片验证。保留上游署名和 GPL 许可证。
- **节目单匹配**：来源 ID 映射到推荐目录的统一频道 ID；每个频道选用一份完整节目单，避免不同来源的节目重叠。仅有过期节目时优先寻找另一来源的当前节目单。
- **节目单缓存**：保留磁盘和失败兜底缓存，新增 ETag/304 条件请求；节目单没有变化时无需重复传输整份 XML。
- **媒体检查**：接受带 UTF-8 BOM 的有效 HLS；`.ts` 地址返回 HTML、图片或可识别错误 JSON 时返回错误并更新状态，不将其缓存成视频。
- **诊断覆盖**：`--probe-all`、`--check-start` 会检查实际启用的附加来源；不再只检测主模式而漏掉新增源。

自动备用选择不承诺跨来源无缝切换。不同来源的分片序号、编码或时间线可能不同，播放器必要时需要重开频道。

## 可选命令

只运行央视频，不启用原网页和地方附加源：

```bash
python cbox-live.py 8767 --api-mode ysp --extra-sources none
```

此配置下推荐目录为央视频 63 路，不会凭空声明未启用的来源。

安装 FFmpeg 后检查央视频：

```bash
python cbox-live.py --api-mode ysp --extra-sources none --doctor ysp-cctv1
python cbox-live.py --api-mode ysp --extra-sources none --probe-all --verify-streams
```

原 App 抓包导入和双模式诊断继续保留：

```bash
python cbox-live.py 8767 --har 抓包文件.har
python cbox-live.py --compare cctv1 --extra-sources none
```

`--extra-sources all` 默认启用央视频和地方源；也可以填 `none`、`ysp`、`regional`。`--channels` 只限制主模式，如需只显示所选主模式频道，同时用 `--extra-sources none`。服务默认遵从 HTTP(S) 代理环境变量，`--direct` 强制直连。默认请求超时为 8 秒，可用 `--timeout` 调整。

节目单缓存位于 `~/.cache/cbox-live/`；使用 `--data-dir ''` 可禁用磁盘缓存。不同来源分开存储；第一次拉取节目单会等待一段时间并在后台继续填充，状态可见各模式 `/diag`。所有来源均明确标记不提供回看。
