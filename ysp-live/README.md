ysp-live 9.5.12-local 本地优化版

这是基于用户提供的 ysp-live v9.5 与 ysp-engine.js 制作的修改版，保留原作者声明；不是原作者的正式发行。Python 入口已整合为单文件，下载 `ysp-live-v9.5.12.py` 即可运行，无需同目录的 `ysp_*.py` 模块。Node 伴生引擎仍为可选增强。

1. 启动与升级

需要 Python 3.10+；伴生引擎需要 Node.js 20+（建议22/24）。没有 pip 或 npm 第三方依赖。本次实际验证环境是 Linux、Python 3.12、Node.js 24。

```sh
python ysp-live-v9.5.12.py 18767 --data-dir ./data
```

启动后在播放器订阅：

```text
http://服务器IP:18767/all.m3u
```

浏览器打开 `http://服务器IP:18767/status` 可查看频道状态、节目单、回看入口并运行诊断。状态只反映已观测结果，打开状态页不会自动逐个播放频道。

Python 会自动启动同目录的 Node 引擎，后者只监听127.0.0.1:8787。退出Python会一同停止由它启动的引擎；已存在的外部引擎只在身份检查通过后使用，不负责终止。

仅使用1080p备用路径、不启动设备注册与Node：

```sh
python ysp-live-v9.5.12.py 18767 --data-dir ./data --no-4k --no-engine
```

9.5.12 针对批量测台和后台预取进一步修复：

- 合法频道的 HEAD 请求只返回元数据，不再拉源、登记播放需求或改变选源。冷缓存返回 200 和 `X-Playback-State: unobserved`；已有发布返回 `cached`，不代表上游已验证可播放。未知频道、鉴权失败和非法回看时间仍返回真实错误；实际播放能力以 GET 和状态页为准。
- 高码率预取在拿到串行协议锁后再次核对频道代际和最近播放需求；已经离开的排队任务直接取消，不请求上游、不触发身份重置、不写入频道故障冷却。内部来源探测不再重复登记播放器请求，减少扫描造成的误预热。
- 正在持续播放的频道仍可升级高码率，直接 4K 与显式前台取源保持原策略。

9.5.11 针对与 9.5.3 对比出现的超时回归修复：

- 备用源只有确认成功后才切换模式。JCE 暂时失败且 BK 同时失败时，不再卡在 BK 并跳过主源 120 秒；正在使用的 BK 失败时也可立即尝试主源。
- 默认恢复 9.5.3 的 urllib/socket 逐请求 10 秒超时，不再把主列表和多级子列表压在同一个 10 秒总预算内。继续保留单级 2MiB 大小限制、最多 4 次子列表下钻、最终重定向基址和最高画质选择。EPG 的独立下载预算不变。
- 设备源仍在取源、防抖等待或备用刷新尚未完成时，记为“正在准备”，不当成上游故障累加 5–120 秒冷却。真实下载、授权、列表格式和冻结故障仍保留原有退避。

默认端口仍为 18767。该修复有 9.5.3、9.5.10 与本版在相同故障条件下的对照回归；并不表示已经在用户的设备网络上验证所有频道。

9.5.9 针对六个方面修复与优化：

| 方面 | 具体变化 |
| --- | --- |
| 状态持久化与 400 自愈 | 换身份前原子清空磁盘旧源缓存，保存换新时间、当日尝试次数和代际；新身份保存失败不再假报成功；成功写入后清理历史持久化错误，单条坏缓存不拖累其他频道。 |
| 换台防抖与请求减负 | 按频道记录单调时钟与持续请求；单次点击后离开的频道不做高码率预取；旧任务不能清掉新任务，预取复用已就绪源。直接 4K 频道仍不防抖。 |
| 普通频道冷启动与时间线 | 空缓存时 JCE 首次失败即尝试 BK；已有可用窗口仍保留短暂重试。无 PDT 的旧前缀及冷启动丢弃分片不会重新追加成新内容。 |
| HLS 与重定向 | 支持有界 gzip/BOM 解码、正确的最终重定向基址、内联 data 密钥；压缩播放列表代理后更新响应头。无效媒体元数据拒绝重建，复杂 MAP 语义保留透传。 |
| RAM 缓存与并发 | 缓存命中更新 LRU；临时分片转 RAM 在锁外复制，复制前预留预算，复制失败和关闭均释放预留；慢读者占用继续计入预算。 |
| 反代、时移与输入限制 | 直接 TLS 自动识别 https；仅在 --trust-proxy 下使用 Forwarded/X-Forwarded-Host/Proto；校验主机、端口和重复 Host，限制请求及参数数量，回看结束时间不超过当前时刻。 |

反代建议显式配置 `--public-base-url https://tv.example.com`。使用 `--trust-proxy` 时，反代必须覆盖客户端传来的转发头，并限制用户直连后端。没有信任反代时不采用这些头。Python 备用/回看与 EPG 继续使用 urllib，不恢复额外的 DNS 公网检查；默认画质策略不变。400 换新失败时保留可用回退通道，不会宣称高码率已恢复。

9.5.8 增加以下三项：

- 状态页显示最近观测到的取源、播放列表、分片失败及脱敏原因；节目页区分 EPG 下载、解析、频道匹配和日期数据问题。历史错误不等于当前仍不能播放，后台内容检查也不等于实际解码检查。
- EPG 使用独立后台调度，默认每小时刷新，无需播放器持续请求。全部源失败时保留旧缓存；部分源失败也保留可用数据并在 60 秒后重试。关闭服务时停止调度。
- 按配置顺序读取最多 3 个 EPG 源，按“频道＋北京时间日期”补齐缺失节目，已有主源日期不被备用源覆盖；跨日重叠节目跳过。旧缓存仅补充新源均未覆盖的部分。页面显示各源是否成功、补入条数及下次刷新时间。

继续保留 urllib 播放与 EPG 下载方式、Python 单文件及最高画质优先；旧版文件保留。

9.5.7 修复 EPG 首次加载：启动及获取订阅时在后台预加载节目单；`/epg.xml` 首次 GET 最多等待 8 秒，下载完成即可在同一请求返回 XML。已有缓存立即返回，所有上游都失败或超时仍返回 503，不返回空节目单伪装成功。EPG 下载也使用 urllib，不额外检查 DNS 是否为公网，保留 gzip、下载/解压上限及 XML 解析限制。更新后请在播放器中重新加载 EPG。

9.5.6 将 **Python 备用源与回看播放列表下载恢复为 9.5.3 的 `urllib.request.urlopen()` 路径**：使用系统 DNS/代理和 urllib 重定向处理，不额外检查 DNS 结果是否为公网。使用这条备用路径不再需要 `--allow-fake-ip`。保留每级 2MiB 读取上限、主/子列表共用下载预算和最高画质选择。

设备源与媒体代理沿用原有目标检查；如需让这些路径支持可信代理的 `198.18.0.0/15` Fake-IP，可继续使用 `--allow-fake-ip` 或环境变量 `YSP_ALLOW_FAKE_IP=1`。这项可选设置不是备用播放列表下载的前提。

旧版文件保留供版本对照；本次请下载并启动 `ysp-live-v9.5.12.py`，停止旧进程再启动新进程。

升级时先停止旧程序，备份原文件及数据目录，将原 device-state-rs.json、proxy-cache-state-rs.json 放入新的 --data-dir。不要同时运行新旧进程使用同一数据目录。旧文件格式继续兼容；运行中的会话会重新建立。

2. 本版主要变化

9.5.4 深入稳定性修复：

- 给前台与恢复请求加上来源状态版本。迟到的列表成功不能清掉刚记录的分片故障；迟到的旧请求错误也不能污染已经更新的来源。媒体列表与主列表的资源令牌均识别设备代际。
- 选源提交和播放列表发布共同校验同一状态版本，先提交再发送；迟到请求优先复用已有且健康的最新高画质结果，避免仅因旧请求被丢弃就降级；socket写入不持有频道选源/发布锁。状态快照调整锁顺序，避免与发布互相等待。
- 较旧的异步窗口不会让已发布媒体序号倒退，旧前缀不会被当作新分片追加；重签URL仍正常更新，新分片身份的上游序号重置仍可前进。旧窗口反复出现不会续新媒体推进时间。
- JCE/BK切换、设备代际变化、明确的画质声明变化会清理旧内容/进度证据。旧签名分片已经离开当前窗口或地址已更新时，其迟到故障会被丢弃。
- 保留同一来源上下文内的最后画质声明，过期声明在页面标注“旧声明”。来源仍健康时，已知高分辨率声明过期本身不会允许自动切到已知更低的分辨率；过期的更高声明也不能单独支持恢复回切，仍需要新的声明和媒体证据。
- 空列表、仅包含预加载提示的列表以及伪装含有#EXTM3U的错误页不再记作成功；包含实际PART URI的LL-HLS仍可保留上游语义。
- 排队检测与恢复任务取消时也会清理“检测中”标志；关闭后的结果不再提交。增加pending/cancelled/ignored/inconclusive计数，冻结主列表的故障也计入失败统计。
- 区分本地目标策略拒绝与真实CDN鉴权失败。无法按本地策略探测的目标记为未确认，不据此触发设备源失效反馈；只有确认的当前代际上游401/403/404才反馈设备解析器。
- 备用/回看列表统一用有界HTTP读取，每级最多2MiB、主列表链共用10秒预算，目标DNS等待也使用剩余时间。沿用既有公网CDN允许列表；上游启用新的CDN域名时需更新允许列表，不自动允许私网。
- 画质声明只沿当前主/子列表下载链传播，不把上一条链缓存的父级声明当作本次子列表证据；更具体的声明优先。
- 新增可复现的并发、取消、代际、空流、下载上限等回归，以及相对9.5.3的本地对比，见 [BENCHMARK-9.5.4.md](BENCHMARK-9.5.4.md)。本轮主要提高正确性与恢复可靠性，不声称所有性能指标均改善。

9.5.3 新增（默认尽量保持最高画质）：

- 默认 `--playback-policy quality --quality best`。主列表选择最高声明分辨率，取消原自动策略的1080p上限；同分辨率用带宽辅助选择。独立音轨/字幕分组保留，只筛选视频档位，不把音轨丢掉。`--quality auto` 保留播放器自适应，`fhd/shd` 可显式限制档位。
- 设备自动档优先比较接口实际声明的宽高；声明不足时保留36p等已知服务档位偏好，不从档位名称伪造分辨率。Python备用接口仍使用其支持的API档位，`best`不等于上游保证提供4K/8K。
- 按来源记录主列表实际声明的分辨率、带宽与CODECS。两边画质可比较时，质量策略不会因为另一来源延迟更低或服务优先级更高就切到较低分辨率。声明不足时沿用设备、备用、Node的优先级；不能据此保证真实解码画质。
- 默认有界后台分片内容检查：每来源最短30秒一次，最多读取64KiB，2个工作线程、最多8个排队任务。优先复用已完成媒体缓存；可跟随最多3层主列表，在直播窗口足够长时检测倒数第二片，减少刚发布分片暂未到达CDN的误判。
- 可识别空响应、HTML/JSON错误文档、TS/fMP4/音频前缀及非空加密内容。未知格式、超时和临时DNS问题记为“未确认”，不单凭检测超时降低当前画质。Range被拒绝时仅在零偏移做一次普通GET确认，仍执行同一字节与时间上限；不完整/无效Range会报告错误。前缀可用不等于视频可解码。
- 自动恢复仍要求两次分片推进，开启后台内容检查时还要求近期内容检查通过。明确分片授权失败会反馈到当前设备源代际；旧代际的后台结果不能覆盖新代际。
- 播放列表解析结果改为不可变共享对象，128条/保守估算8MiB预算/15秒有效期；同一主体只解析一次。相同来源与主体复用发布结果，每次请求仍检查媒体是否冻结，避免用缓存掩盖停滞。
- TCP等待队列随连接上限设置（16至256），减少并发新连接的额外重试等待，活动连接准入限制继续生效。新增本地可复现对比脚本和原始结果，详见 `BENCHMARK.md`。

9.5.2 新增：

- `/status` 是内嵌页面，不需要外部网页文件或前端依赖。显示频道来源、列表声明分辨率、请求耗时、媒体推进、节目单和主动诊断。
- 按频道保持当前可用来源。失败按5、10、20…秒退避，最多120秒；回切前至少保持当前来源30秒，并要求更优先来源两次不同分片的成功观测。恢复探测由有界后台池执行，每个来源最短间隔30秒；仅成功获取主列表不会认定媒体恢复。
- 选源仍按设备源、Python备用源、Node引擎的优先级工作，不凭一次请求耗时就降低画质。Python备用源内部保留JCE/BK恢复机制；分片令牌变化不会被当作媒体推进。
- 新增可配置XMLTV/XMLTV.gz接入、本地内存与磁盘缓存、上次有效缓存回退。EPG启动时预加载并按时后台刷新，失败重试间隔60秒；首次XML请求限时等待，仍不可用时返回503和Retry-After。默认源沿用原订阅中的两个EPG服务，不保证第三方服务可用。
- 订阅的url-tvg指向本地 `/epg.xml`，EPG频道ID与订阅统一。支持ETag条件请求。状态页展示正在播、接下来和节目回看链接，也可手动输入时间生成回看入口。
- `/api/diagnostics` 下载脱敏报告；`/api/diagnose?channel=cctv1` 显式触发分层检查。主动诊断有并发、队列和30秒重复请求限制，不发布或切换播放时间线。9.5.3已从HEAD元数据检查升级为限量分片GET，仍不验证解码。

此前已实现：

- 同一分片一个上游下载、多个独立读取者，首个观众断开不会取消其他人的下载。
- 进行中内容使用临时文件与独立读游标，完成缓存由不可变分块构成，避免原先bytearray转bytes整片复制。慢读者持有的已淘汰缓存仍计入RAM预算。
- 下载并发、客户端连接、临时文件字节、单资源大小、读写期限都有上限。线程启动和关闭失败会归还容量。
- 设备解析、会话初始化、前台/后台刷新共享结果；修复双重失败计数、冷却绕过、旧请求覆盖新缓存和跨入口列表缓存抖动。设备源前台最多等默认2秒，后台可继续完成。
- 分离列表请求成功与媒体推进；冻结流、分片401/403/404会按频道与源代际降级和受限重建。
- JCE保留单调媒体序号，改写标签URI，保留KEY/MAP/BYTERANGE/PDT，AES-128隐式IV在重新编号前显式化。修复重签地址、时区比较和重定向基址。
- 切源边界保留在输出窗口里，HEAD只读；不能可靠对齐的格式通过 X-Stream-Restart: required 标明可能需要播放器重开，不承诺所有编码/格式无缝切换。
- 回看参数严格校验，错误或源失败不会静默播放当前直播；显式 fallback=live 可允许直播降级。
- 分片使用服务器登记的短期资源令牌，任意Base64 URL不再能充当代理授权。每次连接/重定向检查目标、DNS地址和端口，拒绝非预期私网及HTTPS降级。
- Node侧增加连接池、并发与队列限制、短列表缓存/播放地址缓存分离、同频道请求合并、失败退避、流式HEAD/Range、冻结识别和优雅退出。
- 原子持久化、受限DNS缓存与daemon工作池避免损坏状态或阻塞退出。

默认画质优先；切换后仍需播放器支持上游实际编码。要保留原有来源优先级并限制备用到1080p，可使用 `--playback-policy stable --quality fhd`。节省流量模式默认备用shd和设备10p，显式参数可覆盖；它不会修改频道名字冒充画质。

普通JCE/BK播放列表通常让播放器直接访问CDN，媒体不经过Python的RAM缓存。共享下载和cache参数主要影响设备协议与伴生媒体代理路径；相同频道可以节约上游下载，对观众的出站带宽仍随人数增加。

3. 常用参数

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| --cache-mb | 200 | 已完成分片RAM预算，0真正关闭该缓存 |
| --inflight-mb | 256 | 共享下载临时文件总预算MiB |
| --temp-dir | 系统临时目录 | 临时文件位置，空间需求受inflight预算限制 |
| --download-workers | 8 | Python上游媒体下载并发 |
| --max-connections | 64 | Python客户端连接上限，超出快速503 |
| --client-timeout | 20 | 客户端请求头/写入空闲秒数 |
| --media-timeout | 30 | 单次媒体转发总期限秒数 |
| --foreground-wait | 2 | 前台等待设备播放列表的秒数 |
| --timeout | 10 | 设备协议单次HTTP超时 |
| --quality | 由播放策略决定，默认best | best/auto/fhd/shd；best最高可用视频档位，auto交给播放器 |
| --playback-policy | quality | quality画质优先；stable来源优先级；bandwidth节省流量 |
| --media-probe | background | 后台限量检查分片内容；off只关闭自动检查，显式诊断仍可执行 |
| --device-rate | auto | 设备源auto/36p/10p；指定档位不存在时交给备用源 |
| --no-4k | 关闭 | 禁用设备协议，仍可使用Node回退 |
| --only-4k | 关闭 | 仅4K/8K标称频道走设备协议 |
| --no-engine | 关闭 | 不启动或访问伴生引擎 |
| --links-per-device | 6 | 保留原设备链接配额策略，0关闭本地主动配额检查 |
| --zap-debounce | 10 | 普通频道升级高码率前防抖秒数 |
| --bind | 0.0.0.0 | Python监听地址 |
| --engine-port | 8787 | 伴生引擎端口 |
| --public-base-url | 空 | 反代公开origin，例如https://tv.example.com；不支持路径前缀 |
| --trust-proxy | 关闭 | 只在可信反代环境启用，允许Forwarded与X-Forwarded-Host/Proto |
| --access-token | 环境变量或空 | 可选访问令牌，推荐用YSP_ACCESS_TOKEN传入 |
| --epg-url | 原订阅中的两个EPG源 | XMLTV或XMLTV.gz公网地址，重复指定可配置最多3个，依次回退 |
| --epg-refresh | 3600 | EPG自动刷新间隔秒，最小60 |
| --no-epg | 关闭 | 禁用EPG下载与本地XMLTV服务 |

低内存部署示例（临时目录可放实际可用的磁盘）：

```sh
python ysp-live-v9.5.12.py 18767 --data-dir ./data --cache-mb 32 --inflight-mb 64 --download-workers 2 --max-connections 16
```

临时目录若在tmpfs，文件也会消耗系统内存；--cache-mb限制的是程序的完成缓存，不能代表整个进程或整台机器的总内存。使用磁盘目录会产生持续分片写入，应按设备存储选择 --temp-dir。

4. 访问令牌、反向代理与诊断

可设置YSP_ACCESS_TOKEN，播放器订阅地址使用 /all.m3u?access_token=你的令牌。订阅内频道地址会携带访问令牌，媒体资源使用短期独立令牌；HTTP客户端也可使用Authorization: Bearer。/livez和/status页面外壳不要求令牌；状态数据、诊断、节目单和频道接口要求令牌。可在状态页输入令牌，页面使用Bearer请求API；订阅和回看链接携带query令牌。短期资源令牌重启后失效，重新取得播放列表即可。

公开地址推荐固定 --public-base-url https://tv.example.com。只有可信反代才设置 --trust-proxy；默认不会信任任意客户端传入的Forwarded或X-Forwarded-*。自带白名单只允许既有CCTV及常见CDN域名与公网地址；如果上游以后换到新的CDN域名，应审查后同时更新Python与Node白名单，不能关闭私网校验。

- /livez：进程存活，正常200。
- /health 与 /readyz：当前设备协议或已观测频道是否就绪；冷启动未拉取媒体时可能503。不是所有64个频道逐一可用的保证。
- /status：频道状态、节目单、手动回看、主动诊断和报告下载。
- /api/channels：被动读取频道状态和选源观测，不主动拉流。
- /diag、/api/diagnostics：只读脱敏诊断；配置访问令牌后受保护。
- /api/diagnose?channel=cctv1：显式触发播放列表、DNS策略与限量分片内容检查；重复请求加入同一任务。
- /api/epg?channel=cctv1：节目列表、正在播与接下来；GET按需触发后台更新。
- /epg.xml：本地XMLTV，EPG源不可用时优先保留旧缓存，并通过X-EPG-Stale标明过期。
- /api/catchup?channel=cctv1&start=...&end=...：校验时间并生成回看链接，不会提前承诺上游可播。
- /all.m3u、/<频道>.m3u8：保留原订阅与频道入口。
- /proxy、/proxy.ts、/engine_proxy：只接受程序生成的短期资源令牌，不再接受任意目标URL。

分片状态可通过X-Cache区分HIT-RAM、SHARED、MISS-UPSTREAM、BYPASS。列表响应的X-Source、X-Source-Epoch和X-Stream-Restart用于判断来源及切源；它们不会改变播放器对编码格式的支持。

5. 回看与画质

回看支持start/end（Unix秒、毫秒或带时区ISO）及原playseek格式。无时区的日期按中国标准时间解释。显式无效、未来或倒序范围返回400，不支持频道返回422，上游失败返回502。请求窗口最多7天、单次最多24小时是本地校验上限，实际可用范围取决于上游。只有显式加fallback=live才在回看失败时继续直播。

--quality控制Python备用档位及经过Python的主列表选择；设备直接返回媒体列表时，用--device-rate控制设备协议档位；Node协议请求保留原档位，经过Python的主列表再按策略筛选。频道名和档位标签不等同于实测分辨率/码率，实际画质及codec需要真实播放器确认。复杂LL-HLS或无法安全重新编号的加密格式保留原列表，可能需要播放器重开。

EPG配置示例：

```sh
python ysp-live-v9.5.12.py 18767 --data-dir ./data --epg-url https://example.com/epg.xml.gz --epg-refresh 3600
```

也可用 `YSP_EPG_URL` 配置逗号分隔的源。显式 `--epg-url` 覆盖环境变量；`--no-epg` 禁用。EPG启动时预加载，独立调度按配置间隔刷新；获取订阅和节目接口也可触发到期刷新，状态和健康检查不触发下载。多个源按频道和北京时间日期补齐，低优先级来源不覆盖已有日期并避免跨日重叠。EPG通过urllib使用系统DNS/代理和重定向处理，不额外检查DNS结果是否为公网。首次XML GET最多等待8秒，已有缓存立即返回；HEAD不触发下载。压缩下载最多8MiB，展开XML最多32MiB，拒绝DTD/实体声明；保留匹配本地频道、过去7天至未来2天内的节目。无时区的XMLTV时间按UTC解释；手动回看使用浏览器本地时区转换的Unix秒。

EPG缓存写在 `--data-dir/epg-cache.json`。磁盘写入失败时仍保留内存中的有效节目单。节目单仅用于展示和生成链接，不增加上游回看时长；回看频道支持是本地能力表，`verified=false` 表示尚未实际请求上游验证。

6. Node可选配置

单独运行：node ysp-engine.js 8787。YSP_ENGINE_HOST默认127.0.0.1。其余环境变量均以YSP_ENGINE_开头：MAX_REQUESTS(64)、MAX_CONNECTIONS(128)、MAX_UPSTREAM(24)、MAX_QUEUE(64)、TIMEOUT_MS(10000)、RESOLVE_TIMEOUT_MS(25000)、SEGMENT_TIMEOUT_MS(30000)、MAX_PLAYLIST_BYTES(2097152)、MAX_SEGMENT_BYTES(36700160)、STALL_MS(45000)、SHUTDOWN_MS(5000)。Python启动子进程时会显式设定本机监听、端口和2秒退出期限。

Python的urllib及媒体代理保留HTTP_PROXY/HTTPS_PROXY/NO_PROXY环境配置；直连媒体连接使用经过校验的DNS地址与正确TLS主机名。Node媒体传输使用内置直连连接池，不把HTTP_PROXY自动解释为代理连接。
