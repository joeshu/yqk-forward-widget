# R3 验证报告

## 变更

- 控制接口的最小间隔锁覆盖等待、请求执行和完成时间更新，避免并发线程同时通过节流检查。
- 每个设备 slot 使用独立会话锁；同一 slot 的并发冷启动或过期会话重建只执行一次 bootstrap。
- 生产快速初始化等待启动遥测和预热流程结束后再发布会话，减少初始化请求与频道解析交错。

## 验证

- Python：`python -m unittest discover -s tests -v`，32 项通过。
- Node：`node tests/engine.test.js`，5 项通过。
- 真接口：使用已注册设备状态，不创建或轮换身份。R3 生产 bootstrap 的设备启动、云端设备查询、心跳和预热主流程返回成功；同一会话下 CCTV1 与 CCTV4K 的 `live/v1/01` 在该次对照中都返回 HTTP 400，错误响应的时间字段相同。上游错误没有返回媒体地址，因此本次无法探测编码分辨率，也不能确认真实 4K。

R3 修复解决的是本地并发与初始化时序问题；当前证据显示这两项修复没有消除上游 live 接口的 400。此前 BK 的 CCTV4K `uhd` 实测码流仍为 1920×1080，不能视为真 4K。
