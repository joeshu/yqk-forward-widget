# ysp-live v9.5 本地优化版 R2

本包基于用户提供的 v9.5 源码及上一轮本地优化继续修改，非原作者正式发布。原作者 README / PDF 保留用于参考，本次变更及验证结果以本说明和《验证报告-R2》为准。

## 启动与升级

```bash
python3 ysp-live-v9.5.py
```

订阅地址仍为 `http://localhost:8767/all.m3u`；局域网播放器将 localhost 替换成运行设备的 IP。

升级前停止旧实例并备份。替换 Python 和 JS 文件，继续使用原数据目录；状态文件名、原有参数和频道订阅入口不变。重启后重新加载频道播放列表，旧的分片签名链接会失效。

Python 要求 3.10+；可选 Node 引擎建议 Node.js 22+。本次使用 Python 3.12.14、Node.js 24.19.0 验证。代理实现使用 Node 自带模块，不依赖 Node 24 新增的 Agent 环境代理功能，也没有新增 npm / pip 依赖。

## R2 新增优化

1. **环境代理直接可用**：去掉 Python 强制关闭代理的设置；控制面、播放列表和分片转发统一支持 `HTTP_PROXY` / `HTTPS_PROXY`，也支持小写变量和 `NO_PROXY`。Node 提供相同的 HTTP 转发代理、HTTPS CONNECT、Basic 代理认证能力。保持 TLS 证书与目标域名校验，本机网关/伴生引擎始终直连。
2. **网络失败时切换备用源**：JCE 的断连、超时及无效结果也会尝试 BK，不再只处理一个特定废弃域名错误。临时失败后隔一段时间再探测 JCE，避免长期停留在故障状态。只读网络请求最多重试一次；注册等控制写请求不自动重放，HTTP 400 也不因重试规则被反复请求。
3. **频道 400 的处理更克制**：频道播放接口返回 400 时保留设备身份，记录频道冷却并回退，不直接废弃身份。修复同一次错误在内外两层重复计数的问题，首次冷却恢复为 15 秒。
4. **所有备用分片经过网关**：JCE / BK 的播放列表也改写为带签名的网关地址，包括已解析的 KEY/MAP 等 URI 属性。播放器不需要单独配置出站代理；分片统一利用网关的缓存、安全检查、Range/HEAD 转发和并发控制。
5. **Web 引擎刷新更及时，减少重复鉴权**：同一频道并发解析合并；播放列表按目标分片时长刷新，TTL 为 1～5 秒；独立复用最多 60 秒的播放地址，避免每次刷新播放列表都重新完成鉴权。失效地址会被清除；GET 支持 HTTP/HTTPS 和重定向。
6. **来源与清晰度不混淆**：播放列表响应带 `X-Playback-Source: device/jce/bk/web/catchup`，表示实际链路。`X-Resolution-Verified: false` 明确表示网关没有逐流解码确认分辨率。诊断不再因设备会话就绪就把所有频道标为“4K/高码率”；健康检查增加近期播放列表来源。分片流的分辨率应以播放器或 FFprobe 检测为准。
7. **切源标记兼容**：来源变化时注入 HLS discontinuity；`EXT-X-DISCONTINUITY-SEQUENCE` 不再被误当作已经存在的 discontinuity 标记。

## 保留的第一轮优化

- 服务端 HMAC 签名分片地址，默认有效期 15 分钟，拒绝旧的无签名代理请求。
- 上游协议、域名、端口、公网 IP 与重定向检查。直连时直接连接已验证 IP，并验证 HTTPS 原始域名证书。
- Node 引擎只监听 `127.0.0.1`；最近输出可在 `/diag` 查看，进程异常退出后退避重启。
- 频道冷启动、SWR 与后台循环共享每频道进行中的刷新任务。
- Python 请求线程上限 64，分片下载并发上限 8，单分片上限 35 MiB；Node 分片并发 8、解析并发 8。流式转发，下载异常或客户端断开时关闭上游。
- 真正的 LRU 内存缓存、同一分片下载合并；`--cache-mb 0` 可禁用缓存。缓存大小不等于进程总内存上限。

## 代理配置

默认自动读取已有环境代理，未配置时直接连接。例如：

```bash
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
python3 ysp-live-v9.5.py
```

`HTTPS_PROXY` 表示用于 HTTPS 目标的代理，本版要求代理地址本身使用 `http://`；HTTPS 上游通过 CONNECT 和 TLS 连接。支持 Basic 认证，不支持 SOCKS 或代理本身为 HTTPS 的模式。不支持的代理类型会明确失败，不静默切换连接方式。

在允许直连的实际部署环境，可显式忽略环境代理：

```bash
python3 ysp-live-v9.5.py --direct
```

或者设置 `YSP_DIRECT=1`。不要在没有直连网络的环境使用此选项。

代理模式仍先检查目标域名及本机解析结果。最终远端连接由配置的可信代理执行，其远端 DNS 无法像直连模式一样由本程序固定；直连的 IP 固定机制保持不变。不要把不可信代理配置成网关的出口。

## 验证

```bash
python3 -m unittest discover -s tests -v
node --test tests/engine.test.js
python3 -m py_compile ysp-live-v9.5.py
node --check ysp-engine.js
```

共 30 项 Python 测试、5 项 Node 测试通过。新增测试包括：真实本地转发代理、HTTPS CONNECT、TLS 与认证隔离、环境代理下的内网地址拦截、只读请求重试、JCE→BK 及恢复、频道 400 不换身份、不重复计数、分片/密钥地址签名、Web 解析合并及刷新时复用鉴权。测试需要本机 `openssl` 生成临时证书；私钥仅在测试临时目录中生成并删除。

真实媒体验证无需适配器：正常启动 R2，在当前环境继承已有代理，验证 CCTV-1、湖南卫视、CCTV-11、CCTV-4K 的播放列表与经网关转发的分片，四路分片均由 FFprobe 确认含 1920×1080 H.264 视频和 AAC 音频。独立启动 Web 引擎也通过真实媒体检查，间隔刷新后播放列表推进。

## 已知边界

- 真 4K 高码率设备接口仍返回上游 HTTP 400。本版改善冷却和回退，不能消除远端接口限制。CCTV-4K 此次实际播放的是 1080p 备用流。
- 仅完成代表性频道与短时媒体抽测，未轮巡全部 64 频道、未进行 GUI 播放器音画同步或多小时压测。
- 健康接口 `ok` 表示网关进程存活，`playback.playlist_ready` 表示最近成功提供过播放列表，不代表每个频道都可播放或实际清晰度已经确认。
- 真实 CDN 本次可能忽略 Range 并返回完整 200；网关按上游状态透传，不凭空生成 206。
- 签名密钥保存在当前 Python 进程内。重启、升级、过期后需重新加载播放列表。缓存禁用、Range、HEAD、首个下载失败或无法缓存时，同一分片的并发等待者可能收到带重试提示的 503。
- 上游 CDN 域名或接口变化可能需要更新内置列表。没有新增整个网关的用户鉴权。
