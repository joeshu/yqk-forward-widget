## 本轮实际修复
- 播放器和列表按安全区重排；在 viewDidLayoutSubviews 中处理宽高变化。
- 日志独立工具栏：关闭、复制、清空。避免日志遮住原关闭按钮。
- 日志文本刷新合并至最多每秒 4 次（主队列仍逐条接收日志，后续可继续优化）。
- 八个 SDK 回调切回主队列，拒绝非当前播放器实例的回调。
- 用户换台递增播放代次，延迟重连同时检查代次、播放器实例和频道 ID。
- 4000–4999 错误不再盲目自动重试；具体 SDK 错误分类仍需手册细化。
- Python 构建限定 ios-arm64 设备切片，取消模糊匹配。

## 尚未解决 / 不得标为已完成
- 重用同一 SDK 实例时，回调没有携带业务代次；同实例旧回调仍难与新播放区分。需引入独立 delegate-session 代理或 SDK 提供的请求标识。
- PyHost.stop 不等于 HTTP 服务 shutdown，暂不能承诺可靠停止/重启。
- CPython 的 ssl、扩展模块、证书路径和 /health 必须真机验收；Linux 跑通脚本不等于 iOS 内置插件跑通。
- APTV-COMPARISON.md 之前的“已实现”只表示代码存在，不表示编译或设备验收通过；包括 PiP、跨源换源、手势等。
- CDN 回读非空不能证明实际命中对应 CDN；需记录实际媒体连接 host。
- TS start code 的简单计数不能证明 ES 加密；NAL type 24 不能单独判定为非法加密指纹。之前的相关结论证据不足。
