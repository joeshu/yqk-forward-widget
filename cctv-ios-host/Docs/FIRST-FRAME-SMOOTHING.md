# 首帧到连续播放的缓冲过渡

用户反馈首帧后启动较慢并短暂停顿。本轮定位到可造成该表现的宿主逻辑：AVPlayer首帧回调立即将前向缓冲目标由1.5/3秒提高至12秒；Cicada首帧回调重新提交配置并提高高水位。首帧只证明一帧已可显示，不证明连续播放和网络吞吐已稳定。没有新的真机日志，不能将该代码路径直接判定为本次设备停顿的唯一原因。

修改：

- AVPlayer首帧不再立即提高缓冲目标；真实进度累计推进至少5秒、当前正在播放且已缓冲足够目标数据，才扩容。保留系统自动防卡顿策略。
- 首帧后一次性主动启动的缓冲余量提高到至少1.5秒，并随倍速提高，减少薄缓冲下强行起播后再次耗尽。
- Cicada首帧不再调用setConfig，高水位保持2500ms；真正卡顿和用户调整速率时仍可更新配置。
- 状态文案按AVPlayer当前状态显示，不再把已显示首帧但仍等待缓冲直接写成正在播放。
- 诊断新增playback_buffer_target_changed，记录目标变化、已观察播放时长及缓冲余量，不记录媒体URL或凭据。

验证：完整Python回归865项，801通过、64按平台跳过；后续状态文案/诊断小改另通过播放器回退专项。使用gcc直接编译产品头文件中的缓冲策略（仅Foundation基础类型替身），验证首帧、未满5秒、数据不足、暂停、NaN与稳定播放六种场景。未执行iOS构建/真机解码；C策略验证不能代替AVPlayer/Cicada设备表现验证。
