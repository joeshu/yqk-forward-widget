# 资源导入、播放器与全库稳定性审计（2026-11-10）

范围是 `cctv-ios-host`。在已有 JAR 真正执行、DASH 桥接、播放器缓冲与卡顿恢复改动上继续审计，不以降低画质、关闭功能或虚构兼容作为优化。

## 覆盖方式

- `Scripts/source_audit.py` 对 Git 跟踪文件及未忽略的新文件生成逐文件 SHA-256、字节数、源码行数、语法检查和人工检查位置索引。当前扫描 597 个文件、359 个代码文件；136 个 Python、39 个 JavaScript、82 个 JSON、5 个 Plist、8 个 Shell 文件检查通过。
- `Scripts/audit_native.sh` 用 Apple SDK 的 Clang 静态分析全部 `Sources/*.m`，头文件随引用检查。完整打包后另检查需要 CPython SDK 的 `PyHost.m`。CI 保留逐文件报告；诊断必须区分实际问题与编译器保守推断，不能把无编译错误等同于无缺陷。
- 手工检查导入识别/下载/取消/保存、配置读改写、运行时请求边界、媒体元数据缓存、图片加载、日志写入及播放器生命周期。已有行为回归覆盖其他模块；没有声称逐行人工审阅全部第三方源码。
- SDK 二进制只记录完整性并检查接入代码，不声称已审计其内部。真实网络、真机温度/耗电、DRM 和供应商 SDK 解码仍需独立验证。

## 播放器与 JAR 的已有验证

- AVPlayer：实际首帧后才使用快速启动路径；按倍速、卡顿和低电量/内存状态调整缓冲；有界预取下一集并复用 AVURLAsset。
- Cicada：准备、首帧依据真实 SDK 回调；暂停不会被延迟准备回调恢复；进度通知合并；持续卡顿仅尝试一次地址刷新并保留位置；修正动态调用的标量 ABI。
- 无 JIT 的 Zero JVM + JavaHost 在 iOS 模拟器真实执行 DEX 测试爬虫，首页/分类/搜索/详情/播放五个操作后由 AVPlayer 显示视频帧；重复操作复用 JAR 下载与转换缓存。证据见 Actions 运行 `42761208957` 的 JAR smoke artifact。
- Cicada 适配器的回调与状态机用可控 SDK 行为夹具验证。这不等同于真实 Cicada 解码器已通过所有格式或真机性能测试。
- 用户指定的采集订阅返回 HTTP 403，尚不能验证其中站点；加密 HJS 需要公开格式或合法密钥。没有将这些站点标记为已实播通过。
