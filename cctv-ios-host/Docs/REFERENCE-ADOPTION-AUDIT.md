# Playback Reference Adoption Audit

Research checked on 2026-10-24:

- [TVBox-tvs](https://github.com/yuluoos/TVBox-tvs) is a Flutter shell whose repository currently manages release artifacts and documentation rather than publishing the application source. Its docs describe a **PeekPro-only VOD subscription** and explicitly say native TVBox config compatibility is not guaranteed. The docs do not publish the PeekPro schema. Therefore CCTVHost's TVBox `sites`/`lives` JSON importer is a separate format and must not be presented as a PeekPro importer.
- tvbox-silicon's [`Catalog.swift`](https://github.com/jo32/tvbox-silicon/blob/main/Sources/TVCore/Catalog.swift) maps HTTP CMS sites through `filter=true`, `wd/quick/pg`, `ac=detail/t/pg`, `ac=detail/ids`, and `play/flag`; it also carries `ext`, source headers, response headers, `UA`, `playUrl`, and multiple playback choices into its catalog flow. CCTVHost adapts those type 1/4 HTTP JSON contracts directly into its existing home, category, search, detail, route, episode, and playback flow; script packages continue through the existing Python/Node/JavaScriptCore importers. Its JSON adapter preserves source query parameters and recognizes a server error message when playback returns no address. Global search reports each source independently, runs at most three source jobs concurrently, serializes provider requests within each plugin session, and only starts a service the user explicitly taps. It accepts different CMS success codes when the response contains usable data. Type 3/JAR is intentionally unsupported.
- The follow-up forwards selected TVBox category filters as query fields while reserving protocol/authentication keys, resolves relative poster URLs against the site's API directory, and retains `parse`, `jx`, `playUrl`, response headers, and alternate qualities through playback handoff. Failed provider searches remain separate from successful providers; partial searches are labeled and retry only the failed providers. Search order uses a bounded, expiring source-health cooldown record. These are protocol-adapter behaviors; no provider playback has been verified on an iPhone in this environment.
- [yl_player](https://github.com/yuluoos/yl_player) is a federated Flutter playback plugin, not a drop-in Objective-C framework. The checked Apple package is `0.3.0-dev.5`, targets iOS 15, and depends on Flutter/Dart (`Flutter >=3.44`, Dart `^3.12`) plus `yl_player_media_core`. Its documented session model distinguishes assessment, committed load, media readiness, and first frame; replacement invalidates old session handles. The Apple media core redistributes LGPL FFmpeg components and Opus under separate notices. Embedding it in CCTVHost would require Flutter add-to-app, a new build chain, binary-size review, lifecycle integration, and license/relinking review. CCTVHost keeps its native UIKit/AVPlayer implementation and adopts portable lifecycle and UI ideas instead.

This pass adds local watch history and resume prompts, per-title intro/outro markers, playback speed and aspect-ratio controls, keep-awake control, and quality switching that preserves position when the replacement stream supports seeking. History is keyed by source, provider, title, route, and episode IDs; it stores progress and display metadata only. Resolved media URLs and request headers are not persisted. Metadata cache is limited to home, category, and search lists because detail episodes may carry signed URLs. The history page supports confirmed single-entry removal as well as clear-all. CCTVHost already fences stale request/player callbacks and distinguishes AVPlayer readiness from its observed first video frame; this is not equivalent to `yl_player`'s full typed session and failure API.

The playback follow-up keeps the TVBox JSON API adapter attached through in-player episode selection and resolution, instead of routing those requests to a local plugin port. It also adds a user-toggleable automatic next-episode action (enabled by default) that advances only within the currently selected route and records a diagnostic event. Route changes try to preserve the same episode identity; quality changes preserve position and play/pause state; a stalled stream gets at most one generation-scoped re-resolve attempt before the user must retry or change routes. The existing home-first media entry, configurable continue-watching/favorites/pinned-source modules, source/site selectors, global black/white theme, paged episode selection, and landscape player remain the app's native implementation.

No PeekPro parser, JAR runtime, or undocumented private protocol is claimed. Global search and type 1/4 mappings are code-level implementations based on the public protocol shape; real-world provider compatibility still depends on each endpoint's response fields and playback restrictions. The TVBox reference does not publish app source or reliable UI captures, so this audit uses its repository behavior without claiming pixel-level UI verification.

These changes are code-level implementation only. iOS compilation, device playback, subtitle/codec behavior, and resume seeking against individual providers still require Xcode and device validation.

## CCTVHost implementation follow-up (2026-10-24)

- A standalone MacCMS API source can be added from the resource import sheet. It is stored as a catalog entry and appears in the existing media source picker; it does not start Python/Node/JSC. The client uses `ac=videolist` for lists/search/categories and `ac=detail&ids=…` for details, and accepts JSON or bounded MacCMS `<rss><list>/<class>` XML. XML parsing disables external entities and caps nodes/text. Episode URLs and source headers flow into the existing playback handoff. The endpoint remains “not checked” until selected and read.
- Native catalog `capabilities` and `providers` responses are now local, so opening or searching a TVBox/MacCMS source does not spend a network request on metadata that is already known. API reads update the bounded source health cooldown; this measures API readability, not video playback.
- Global search history is opt-in, local-only, capped at 20 terms, and can be cleared or disabled. Per-source/provider browse state is persisted with a 32-entry cap and restores category, filters, query, page, and scroll offset.
- When a source requests web playback, the playback page offers “尝试原生” after returning from its web player. This sends the same resolved URL to AVPlayer and does not claim playback success until AVPlayer reports readiness/first frame.
- This follow-up has not been compiled with Xcode and has not been validated against a live MacCMS endpoint or on an iPhone. XML variants outside the documented `rss/list/video/class` shape still require provider samples and device verification.

## Stability audit fixes (2026-10-25)

- Native catalog results are now type-checked before dictionary access. Media API responses are accumulated through a data delegate and cancelled once they exceed 2 MiB, including chunked responses without a declared length.
- Playback history no longer stores URL-shaped route or episode identifiers. Existing entries are migrated in place to route/episode index keys while retaining progress and display metadata.
- Python Spider and managed Python service imports resolve package-local modules beneath per-session module namespaces instead of sharing top-level module names through `sys.path`. JavaScriptCore calls that time out mark that session unresponsive and reject further queued operations until stop succeeds.
- Search history controls live in the page header so the navigation back button remains available; disabling history clears saved and in-memory browse keywords.
- These fixes have not been built or run on iOS. The current environment has no Xcode toolchain, and this pass did not run the test suite.
