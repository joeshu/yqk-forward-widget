Evidence: three user-exported JSONL sessions, build 244, iOS 27.0.1.

## Changes driven by this evidence

1. Keep the first terminal outcome of each playback attempt; a subsequent close
   remains a separate navigation event and cannot erase failure evidence.
2. Bridge a strict, size-bounded whitelist of relay events/fields into global
   diagnostics with the owning service and existing correlation ID. Arbitrary
   plugin messages and URL/credential fields are excluded; the global redactor
   still applies to allowed text fields.
3. Emit manifest-requested and manifest-readable once per registered manifest
   token, without consuming the GET marker on a preceding HEAD. These mean HTTP
   transport/manifest validation only, not decoder success. Tracking is bounded
   with the relay target cache and cleared on eviction/close.
4. Persist content API started/succeeded/failed runtime stages so an interruption
   during a Python category call can be distinguished from module initialization.
   High-frequency proxy/segment operations do not write these checkpoints.

Validation: Python transport tests cover checkpoint success/failure and context
cleanup, manifest event deduplication, HEAD-before-GET, signed URL omission and
bounded tracking. Foundation tests exercise the event parser and reject forged
fields/events. Simulator smoke checks that `failed/404/media_not_found` survives
`screen_closed`. Foundation/UIKit execution requires macOS CI.

## Remaining investigation

A new device export should show whether a failed movie reaches the local relay,
what upstream HTTP/manifest stage fails, and the Python operation active before

require OS diagnostics; these changes do not claim to fix the unknown crash or

## Image allocation hardening (unconfirmed crash hypothesis)

The shared loader already limited compressed bodies to 2 MB and output
thumbnails to 192/1024 pixels, but did not validate source dimensions. It now
creates ImageIO sources with full-image caching disabled and validates metadata
before requesting a thumbnail: positive finite dimensions, at most 16,384 on
one axis and 20 MiPixels total. Oversized artwork shows the existing placeholder
and logs `image_dimensions_exceeded`; missing/invalid dimensions log
`image_metadata_invalid`. Neither condition deletes a resource or blocks video.
The numeric policy runs in a portable C regression test, including 8K, extreme
axes, zero, negative and nonfinite inputs. Existing simulator image-load checks
remain the integration coverage for ordinary images. No supplied log proves
that an oversized image caused either interruption; this closes an allocation
risk found while inspecting their shared rendering path.

The relay also no longer forwards byte Range headers for a known HLS manifest:
its rewritten bytes do not share the source playlist's byte offsets, and a tiny
upstream range could truncate the playlist. This applies both to initial fetches
and refreshes; segment/MP4 Range handling is unchanged and retains its existing
206 regression. The supplied device export does not include upstream request
headers, so this is a compatibility defect found in code, not a proven cause of
those three AVPlayer errors.

## Embedded SIGPIPE policy

`PyHost` explicitly sets `PyConfig.install_signal_handlers = 0`, and the project
had no compensating SIGPIPE policy. A separate local POSIX C process reproduces
termination with signal 13 when writing a closed socket under the default
handler. Python-level BrokenPipeError catches cannot handle a native process
termination. A shared native helper now restores CPython's usual ignore policy
only when the current disposition is SIG_DFL, before interpreter initialization;
an existing ignore or custom SDK handler is preserved. `python_sigpipe_policy`
records -1/error, 0/already ignored, 1/installed, 2/custom preserved. Installation
failure aborts service startup with an error instead of silently continuing.

The subprocess regression verifies default termination, protected EPIPE return,
idempotence, and preservation of a custom handler. This establishes a concrete
embedded-HTTP shutdown risk and tests the protection, but the supplied device
logs contain no signal number: SIGPIPE remains an unconfirmed explanation for
those two exits. A device whose policy was already ignored can still exit for
other reasons.

## Reproduced long-VOD relay failure

A generated 1,000-segment playlist reproduced a deterministic local error in the
old registry: rewriting registered every segment in the same 256-entry LRU as
its manifest. By the time the playlist was returned, the manifest token and
first 744 segment tokens were gone. A player requesting the beginning could
receive the relay's own 404, regardless of upstream availability.

The manifest/refresh registry and segment/key/map registry are now separate.
Segment registration has a hash index instead of scanning the whole registry
for every URI. The segment registry is bounded at 16,384 URL records and does not
cache video bytes. A playlist exceeding that reference budget fails explicitly
with `manifest_entries_exceeded` instead of returning already-expired early
URLs. Registered headers, origins and diagnostic IDs remain part of identity;
closing the relay clears both registries and the index.

A real local HTTP integration fixture now retrieves a 1,000-segment rewritten
playlist, its first segment, last segment (206 Range), and AES key. It verifies
the manifest remains reachable and a second fetch reuses registrations. These
are transport fixtures, not decoded videos or verification of the user's three
remote media hosts. The local 404 defect is proven; its contribution to the
supplied AVPlayer failures remains to be confirmed by device replay.

## Local session errors versus upstream errors

An unknown/evicted relay registration now returns a structured 404 with
`media_session_expired`; a stopping relay returns `media_service_stopping`.
Both record `upstream_status: 0`, since no upstream request occurred. Upstream
404s retain `upstream_http_error` and `upstream_status: 404`. The response has
the same request ID as its diagnostic record; unknown tokens are not logged.
Response writes occur after releasing the registry lock, so a blocked client
cannot hold up other registrations through this error path. The regression
checks lock availability during response writing, GET diagnostics, and HEAD
without a body. This improves diagnosis; it does not repair an unavailable
remote video or prove a decoded first frame.
