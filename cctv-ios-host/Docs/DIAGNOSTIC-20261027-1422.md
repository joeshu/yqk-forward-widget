# Device diagnostics: 2026-10-27 14:19–14:22 UTC

Evidence: three user-exported JSONL sessions, build 244, iOS 27.0.1.

## What the logs establish

- Sessions `99cfef5c` and `ff8e5352` end without a close marker. The next launch
  recovers both as unclosed. Both last recorded UI checkpoints are
  `media_grid_first_cell_will_display` for 88 items from the service on port
  18780. A category request was started without a recorded completion.
- The service on port 18781 initialized in roughly 13–16 seconds in two of the
  sessions; another initialization had not finished when the app exited.
- Recorded physical footprint at the final UI checkpoints was about 51–54 MB.
  These are point samples, not a peak and not evidence excluding a later memory

  The exact cause of either unclosed session remains unknown.
- In session `cda2c12d`, four play API calls returned addresses. Three recorded

## Changes driven by this evidence

1. Keep the first terminal outcome of each playback attempt; a subsequent close
   remains a separate navigation event and cannot erase failure evidence.
2. Bridge a strict, size-bounded whitelist of relay events/fields into global
   diagnostics with the owning service and existing correlation ID. Arbitrary
   plugin messages and URL/credential fields are excluded; the global redactor
   still applies to allowed text fields.
3. Emit manifest-requested and manifest-readable once per registered manifest
   token, without consuming the GET marker on a preceding HEAD. These mean HTTP
   transport/manifest validation only, not decoder success. Tracking is bounded
   with the relay target cache and cleared on eviction/close.
4. Persist content API started/succeeded/failed runtime stages so an interruption
   during a Python category call can be distinguished from module initialization.
   High-frequency proxy/segment operations do not write these checkpoints.

Validation: Python transport tests cover checkpoint success/failure and context
cleanup, manifest event deduplication, HEAD-before-GET, signed URL omission and
bounded tracking. Foundation tests exercise the event parser and reject forged
fields/events. Simulator smoke checks that `failed/404/media_not_found` survives
`screen_closed`. Foundation/UIKit execution requires macOS CI.

## Remaining investigation

A new device export should show whether a failed movie reaches the local relay,
what upstream HTTP/manifest stage fails, and the Python operation active before
an interruption. Native signals, system kills and watchdog causes may still
require OS diagnostics; these changes do not claim to fix the unknown crash or
make the three failed video addresses playable.
