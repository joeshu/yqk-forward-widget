# CCTVHost 真机性能与播放验收

审计基线为 `5abf3d9`、CCTVHost 1.59 (583)。同提交的模拟器 JAR 冒烟在受控夹具上测得首次首页 21.83 秒。Linux 回环 HLS 基准在 150 ms 模拟源站上测得 4 个并发 GET 合并为 1 个。真机基线需要用相同设备和来源分别安装审计版与本次构建后采集。

## 设备和指标

- 使用一台 iOS 17 最低适配机型和一台当前系统机型。每台记录设备型号、iOS 版本、构建号、播放器、网络、冷热缓存、低电量模式及初始温度。在 Wi‑Fi、蜂窝和受控弱网下分别执行。
- 每组执行至少 20 次冷启动、30 次连续切台和 10 次切集。另做 30 分钟直播与点播、锁屏和恢复前台。取首帧 P50/P95、出帧成功率、失败及恢复次数、卡顿次数与累计卡顿、峰值内存，以及相同亮度和音量下的耗电和热状态。
- Instruments 采集 App Launch、Time Profiler、Core Animation、Allocations 和 Energy Log。开启设置中的运行诊断，导出两版 JSONL。以 `correlation_id` 或 `playback_attempt_id` 关联起播及实际首帧事件。按 `jar_request_dequeued`、`jar_archive_ready`、`jar_bridge_returned` 查看排队、归档下载和原生桥接耗时。
- 用同一台设备对比发行优化前后。验收要求核心场景无串台、重复出声、旧请求抢回页面或数据丢失。性能是否提升以同条件对照为准。

## 播放与恢复场景

| 场景 | 验收 |
| --- | --- |
| CCTV 自动、自选、明文自选 | 弱网与授权拒绝时核对所选线路和实际节点。等待起播时切影视库、资源或设置，迟到结果应留在原播放会话。 |
| 订阅 AVPlayer 与 Cicada | 用自有 HLS、MP4、TS、FLV、DASH、RTMP(S) 样本验证对应引擎。模拟断流、首帧超时和错误格式，确认同源重试有上限，备选源属于同台且保留各自请求头。 |
| EPG、M3U 回看和原生时移 | 测两类占位符、跳过保留窗口、原生连点回退和回到直播。分别核对请求接受、定位完成及出画面。 |
| 多源与大列表 | 500 台列表快速滚动、订阅和 XMLTV 超过上限、大海报目录、换源后立刻退页。检查 UI 主线程、内存峰值、取消与恢复。 |
| 多季影视和本机媒体 | 播放两季各自的同集号，退出再进入验证续播。切清晰度后核对档位、进度和凭据作用域。用失效的本地文件、音频中断和不断改变的搜索词检查恢复。 |
| iOS 系统交互 | 前后台、锁屏控制、耳机断开、来电、AirPlay 与 PiP；确认系统控制只作用在当前播放器。 |
| 资源和数据 | 用真实产生的本地列表、三档频道排序、两季历史做备份往返。联网导出合集 ZIP，断网回导检查已收录脚本。验证编辑页与诊断截图只展示允许公开的信息。 |
| JAR 与运行时 | 冷热首页、超时取消、两个插件并行、取消后立即开始新任务，记录超时后实际归还运行资源的时间。 |
