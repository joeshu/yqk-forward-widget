# JAR runtime packaging size and compatibility

Baseline: release **CCTVHost 1.31 (497)**, commit
`87ba8453f3546dbfda43e9e9d8c8a01371982976`. Its IPA is 106,835,077 bytes;
the app's ZIP entries total 257,688,268 uncompressed bytes. Decimal MB are used.

## What is safe to remove

The Android SDK dependency `android-4.1.1.4.jar` contains a framework resource
table and Android system UI images/layouts. The pinned host's
`android.content.res.Resources` implements virtual resource lookups; it does not
read this framework APK table. Remove only `res/`, `resources.arsc` and
`AndroidManifest.xml` from this exact dependency. Keep every class, manifest,
service entry, unknown resource and `assets/` entry. `AssetManager` uses class
loader assets, so the original plugin's assets must remain accessible.

The packaging tool hashes every retained SDK entry before and after rewriting,
rejects an unexpected/signed SDK JAR, and does not rewrite any other JAR.
In the released dependency, 1,698 classes survive byte-for-byte; 5,465 SDK UI
entries are removed. The dependency's archive falls from 12,947,757 to 1,605,907
bytes. Whole-archive DEFLATE-6 estimates fall from 11,867,576 to 1,405,962 bytes;
these are comparative estimates, not the final IPA's compression measurement.

The JDK image is generated twice from the same target classes: the original
profile, and `--strip-debug --compress=zip-0 --no-header-files --no-man-pages`.
`jimage list` must show exactly the same modules and resource/class entries.
`packaging-report.json` in each platform's runtime artifact records both image
sizes, SDK preservation evidence, options, and SHA-256 for all untouched JARs.
The report is build evidence and is not copied into the app. Debug stripping
removes JDK library source/line debug metadata; host and plugin diagnostics are
not stripped. Keeping an uncompressed jimage avoids adding per-class runtime
decompression; the outer IPA still compresses the image.

## What is deliberately retained

The module set remains `java.base`, `java.management`, `java.logging`,
`java.naming`, `java.security.sasl`, `java.xml`, `jdk.zipfs`, `jdk.httpserver`,
`jdk.unsupported`, and `jdk.charsets` (plus any dependencies resolved by jlink).
For example, the host uses management for Android thread CPU time and httpserver
for its local relay. Chinese sites need charsets; XML parsers, service providers,
ZIP filesystems, Unsafe and reflective plugin code need the other modules.
Static jdeps results alone cannot establish an arbitrary downloaded plugin's
reflection or service requirements, so they are not used as a class-removal list.

Bouncy Castle and its signatures, Kotlin, Guava, SMB/WebDAV, QR-code support,
DEX conversion, and unidbg guest Android ELF libraries remain intact. The `.so`
files under unidbg's `android/` directory are emulated guest resources, not
unused iOS/desktop executables. No shrinking, obfuscation, module disabling,
or optional-network-download mechanism is introduced.

## Verification

- Packaging behavior tests verify class/asset/service preservation, unknown
  resource preservation, refusal of signed/unknown SDKs, and pinned patch guards.
- The same actual DEX fixture runs against the baseline JavaHost and the
  resource-trimmed JavaHost. It exercises Chinese charset round trips,
  Bouncy Castle AES/GCM and SHA-256, XML/HTML/JSON, ZIP filesystem services,
  management/logging/naming/SASL, reflective dependency loading, and plugin
  assets before home/category/search/detail/play dispatch.
- The embedded iOS simulator test uses that DEX through the production
  Zero/JNI bridge, performs the same checks, then renders the media result with
  AVPlayer. It also retains archive/media header separation and download reuse
  checks. The complete device-target IPA is built and inspected separately.
- CI records actual IPA and unpacked app byte totals. Final Apple results and
  measured complete-IPA savings are recorded in the PR after the build.

These checks protect the supported runtime surface. They do not establish
compatibility of every external JAR or a subscription currently refusing access.
