# build 251 日志后的服务恢复与诊断改造

## 已实现

- 首页菜单新增检查连接、重启当前资源服务；失联状态卡提供单服务重启。
- 返回前台在 DidBecomeActive 后仅按需检查可见来源；保留内容。后台取消
  浏览器所属探测/元数据请求，延迟检查隐藏页面；不自动启用已停止或从未启动的来源。
- 冷启动沿用原 45 秒准备窗口；已有会话重新检查使用 4 秒预算。准备中的
  Spider 回到准备流程，不能因为短探测预算结束就当成端口死亡。
- 重启按 ID 串行，先执行原停止协议；停止成功后在非 UI 线程通过真实
  loopback connect 验证端口明确拒绝连接。仍可访问、超时或未知时不启动。
  配置在重启期间变更、来源失效或过期回调均不得覆盖新页面。
- 每次健康探测记录开始与唯一完成/取消结果、probe ID、实际次数、最后错误、
  来源上下文；不记录 URL 或正文。Python 补停止请求、HTTP 循环退出、监听关闭检查点。
- 首帧和有效画面尺寸可确认视频；尚未确定的轨道标为 unknown，避免假阴性。
- 进度观察只累计首帧之后、播放中的短时间正向推进，排除明显 seek、暂停和
  suspend 间隔；5/30 秒里程碑和每个 attempt 的结束摘要有界记录。
  该指标为采样证据，不是逐帧解码证明；不能替代人工长播验收。
- 首页同一主队列轮次的重复重建合并；首个空布局仍同步创建。
- 海报沿用缓存/并发去重；404 负缓存 120 秒，429/492 为 60 秒，其他失败 30 秒。
  校验主动取消与普通取消区分记录，不阻塞影片或播放。

## 限制和最小替代方案

没有用户这次失联时的原生 socket 栈，仍不能认定后台使哪个监听失效。
因此不引入无人确认的自动强制重启；以显式单服务重启作为恢复入口。
其他页面的同时启停返回“正在启停”，不合并不同配置或不同用户意图。
停止协议无法确认清理时仍可能需要重开 App，UI 不会假报已恢复。

没有接入 iPhone，本轮无法完成同设备 10 次前后台、10 部影片各 30 秒、
长播、系统回收和内存曲线验收；这些项必须保留为未测。首页合并减少重复工作，
不宣称已有启动速度或内存收益数字。MetricKit 聚合不能作为单会话崩溃根因。

## 验证方法

本地：`python3 -m unittest discover -s cctv-ios-host/Tests -p 'test_*.py'`。
新策略测试编译实际 C 头文件，检查端口监听前/监听中/关闭后的状态、无效端口、
进度中的暂停/seek/悬挂间隔/倍速，以及图片退避。
模拟器 smoke 新增重启重复点击、目标 ID 和来源失效后回调隔离、探测取消检查。
原有 Python 多服务启停、停止失败及端口回归继续运行。

真机需验证：两个 Python 加一个 JS 服务并发，后台前台十轮；主动关闭单个
监听、端口冲突、慢初始化、停止失败、切来源、菜单重试、原分类恢复；每轮导出
独立会话。检查其余服务仍可访问，失败能关联到 probe/attempt，且不重复启动。
