# CCTVHost 0.17.0

## 界面和功能

保留 CCTV / 频道 / 收藏 / 配置 / 设置五个导航。CCTV 仅列出 CNPlayerSDK 官方频道；频道仅列出 M3U/M3U8 订阅，使用 AVPlayer。右上角采用页面专属胶囊工具组，频道/配置页最多三个直接操作；搜索独立显示。各目录保存分组、搜索和滚动位置，并有空列表提示。

配置页可添加链接或导入 UTF-8 M3U 文件（10MB 内，媒体 URL 须为 HTTP/HTTPS）；本地列表复制到本机数据中，不依赖文件提供方后续授权。左滑编辑名称、订阅地址和 XMLTV 地址；长按配置上移/下移。刷新失败保留上次成功频道，并显示失败状态。订阅缓存先显示、首帧后刷新；本机源等待服务可用，不阻塞央视原生播放。

XMLTV 支持普通 XML 与 gzip、时区转换、tvg-id 和 display-name 匹配；读取播放列表 x-tvg-url/url-tvg，手动 EPG 地址优先。默认缓存六小时，下拉可强制刷新；出错保留旧节目单，未匹配时回退到能匹配的央视官方 EPG。长按订阅频道，或播放器选线菜单，可编辑 EPG ID。无回看 URL 时不提供虚假的节目回放。

收藏菜单支持移到首位；列表左滑取消收藏。最近观看可以再次播放和清空。卡片默认静态台标；没有正式播放会话时可手动预览一个 M3U 频道，静音、30 秒后关闭；切页、后台或正式播放会销毁预览。服务页沿用文件、远程链接和手写 Python 导入/代码查看/导出/健康检查/日志；CPython 仍是每个 App 进程只能启动一次，停止后需重开 App。

备份 v2 包括配置名称、本地播放列表文本、EPG 来源与匹配、排序、启停、收藏、历史与偏好；兼容导入 v1。Python 脚本仍单独导出。没有 iCloud。

## 日志发现与速度边界

用户 2026-10-23 02:17 起的日志：兼容复用首帧 5 个样本，中位数 7.74s（6.30–7.95s）；独立实例 4 个样本，中位数 6.92s（4.66–7.75s）；AVPlayer 4 个样本，中位数 3.28s（2.06–3.97s）。样本与频道不完全配对，不能认定独立实例更快。

原生播放在 Python 服务未启动时已慢；应用准备约 0.01–0.07s，VDN 约 1.9–2.8s，随后等待媒体准备与首帧。日志还显示浙江卫视 URL 被传给原生 SDK。修复不假设 Python 是唯一原因：原生入口和选线/重试统一检查 URL，订阅始终走 AVPlayer。开台暂停订阅刷新、台标和 XMLTV 流量；快速点台合并 80ms 内的选择，首帧计时包含该等待。迟到的旧请求不得覆盖新会话。SDK 后台回调另记 raw 时间和 mainLag，日志输出当前实际实例模式和 Python 运行状态。

核实历史：2966473（0.9）尚未加入 Python；f4aee6e（0.10）首次引入。SDK 二进制自初始提交未更换；0.9 已使用 retained wrapper/reset/playLIVE/prepare，不能把后来的慢简单归因于复用。随包手册没有可直接套用的直播秒开缓冲配置，未把点播参数或搜索到的二进制字符串当作已验证直播 API。

## 三个可分别安装的包

- full：0.17.0 完整版，包含真实 CPython，与已有完整版本使用同一应用标识。
- no-python：0.17.0 无 Python 诊断版，同样界面/播放代码；不链接、不打包 Python、标准库及插件。独立应用标识 `com.example.cctvhost.nopy`，服务启动会明确报不可用；仍能播放外部 HTTP/M3U 流。
- baseline09：0.9 播放流程参考包，从历史控制器 2966473 重建，独立应用标识 `com.example.cctvhost.baseline09.nopy`；使用相同 SDK/当前频道目录和打包工具，仅补首帧计时与日志导出。它是诊断参照，不是原封不动的历史 IPA，也不承诺旧版本缺陷已修复。

## 真机对照步骤

三个包使用相同签名工具安装；完整版先导出本机配置后更新。同一设备/网络，不开 VPN 或改变代理；对照包默认配置独立，手动选择相同自动线路。完整版先不启动 Python，再补充服务运行中的一组；关闭列表视频预览。

每个包测试 CCTV1→2→3→1 固定顺序，每次等出画面再切，至少十次；另测完全退出后冷启动，暂停计数被主动取消的切台。记录首帧中位数/P95、失败/卡顿和清晰度。0.9 对照包通过右上角导出日志，其他包在设置导出诊断日志。可运行 `python3 Scripts/startup-report.py 日志1 日志2` 汇总已完成的真实首帧；脚本不会把 itemReady 当首帧，也不会把主动取消认作失败，失败率需同时核对完整日志。

目标是相对 0.16.2 首帧中位数降低 30% 且不增加失败、卡顿；目前没有新版用户真机时延，不能宣称已经恢复早期速度。若无 Python 同代码包仍慢，下一步依据 0.9 同机结果和 raw/mainLag 排查媒体加载/线路，避免继续盲调 Python。
