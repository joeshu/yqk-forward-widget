# 与 APTV 的功能对照与改进清单（2026-10-22）

APTV 是 iOS 上的 IPTV 播放器（M3U 订阅 + 分组 + EPG + 手势播放）。本 App（CCTVHost）目标是
「央视影音原生 SDK + 插件订阅」，不追求复刻 APTV 全部能力，但界面上可以对齐其成熟做法。
下表只列**本 App 已实现 / 计划 / 不做**，不臆测 APTV 内部实现细节。

## 一、已实现（对齐 APTV 的常用体验）

| 能力 | 现状 |
| --- | --- |
| M3U 订阅（多源） | 支持添加/删除/刷新/下拉刷新，源列表持久化 |
| 分组浏览 | 全部 / 央视 / 卫视 / 地方 / 教育 / 订阅 |
| 搜索 | 导航栏搜索框，按名称与 ID 过滤 |
| 最近观看 | 独立分区，最多 8 条，持久化 |
| 台标 | 解析 `tvg-logo` 异步加载 + 内存缓存 |
| EPG 节目单 | 独立页面 + 列表行「正在播」+ 播放器「正在播/接下来」，每分钟刷新 |
| 多线路 | 长按频道选节点；节点经 SDK CDN 偏好注入；失败自动回退 |
| 播放手势 | 单击显隐控件、双击全屏、左半屏上下滑亮度、右半屏上下滑音量 |
| 全屏 | 一键进出，控件自动重排 |
| 锁屏/控制中心 | Now Playing 标题 + 播放/暂停远程命令 |
| 断流重连 | 两次退避重连（1s / 3s），同一频道才继续 |
| 续播 | 启动后自动恢复上次频道 |
| 首帧统计 | 播放器信息行显示「首帧 x.xs」 |
| 内置插件 | 一键启动内置 Python 插件（ysp-live）并自动订阅其 `/all.m3u` |
| 排障 | 全屏日志浮层 + 常驻最后一行日志 + 可选文本复制 |

## 二、值得继续做（按性价比排序）

1. ✅ **收藏（星标）**：列表左滑加/取消，收藏项置顶排序（0.13.0）
2. ✅ **多源同频道自动换源**：订阅合并时按频道名记录备用地址，播放失败自动切下一个源（0.13.0）
3. ✅ **EPG 缓存落盘**：写入 Caches/epg-cache.json，6 小时有效，冷启动直接命中（0.13.0）
4. ✅ **画中画**：`AVPictureInPictureController`（仅订阅源可用），Info.plist 已加 `audio` 后台模式（0.13.0）
5. 🔶 **列表增量刷新**：EPG 更新改为 `reloadRows` 定位单行；`reloadData` 仍用于筛选变化
6. ⬜ **时移/回看**：插件 m3u 已带 `catchup-source`（`?playseek=${b}-${e}`），需要构造回看地址并验证鉴权，独立功能块
7. ⬜ **播放器信息面板**：分辨率/码率/缓冲/CDN 节点（SDK 只暴露部分字段，待确认）

## 三、明确不做

- **iCloud 同步**：自用工具，收益低。
- **多主题/换肤**：维护成本高，收益低。
- **内置 DNS/代理**：与播放无关，超出范围。
- **复刻 APTV 的脚本 API**：我们用的是「内嵌 CPython 直接跑插件」，而不是定义一套宿主 API。

## 四、当前风险点（优先级最高）

1. **内置 CPython 尚未在真机验证**：构建链路刚打通（需要 `Python.framework` + stdlib + `PyConfig.home`），
   首次运行可能出现 stdlib 路径、`_ssl` 缺失或线程/信号兼容问题；日志已重定向到 App 内面板，便于定位。
2. **节点线路的 CDN 偏好是否生效**：`configSDK_CDN_LIVEDefaultCDNInfo:` 的入参形态（数组 vs 单对象）尚未用真机确认，
   日志里会打印回读值。
3. **KS 线路 404**：线路本身失效，不是代码问题；若要彻底解决，应在菜单里做 HEAD 探测并置灰。
