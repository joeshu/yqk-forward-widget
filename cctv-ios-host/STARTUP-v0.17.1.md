# CCTVHost 0.17.1：当前版本起播调整

根据用户 `cctvhostno.log`（0.17.0 无 Python 包）处理当前版本，不再制作历史对照包。

## 日志结论

5 次原生首帧：11.55、7.33、7.54、5.98、7.92 秒，中位数 7.54 秒。
宿主选台到 prepare 调用约 0.15–0.18 秒；VDN 成功约 2.29–3.57 秒；其后到画面仍约 3.68–8.15 秒。
日志没有暴露 SDK 内部各个媒体/密钥请求的耗时，因此不能进一步断定是 HLS 分片、DRM、解码还是网络造成该段等待。无 Python 包仍出现等待，不能归因于 Python。

## 实际调整

- SDK 初始化返回后 0.15 秒续播，原先固定等待 2.5 秒；实例预热提前到 0.05 秒。
- 选台使用下一个主线程周期合并连续点击，去掉固定 80 毫秒延迟。
- 同一频道正在连接/播放时仅展开播放器，不重复 stop/reset/VDN。失败或超时后仍允许重新选择。
- 新增“原生播放器快速起播”设置，默认开启。在 SetupPlayer 后下一个主线程周期取得已配置完成的 Cicada 内核，将起播门槛最多降至 150 ms、再缓冲门槛最多降至 1000 ms。SDK 原值通常为 500/3000 ms。
- 首帧或错误时恢复原始缓冲；仅修改现有 config 的上述两项，保留 license、UDRM、referer、最大缓冲、网络超时等设置。不会导出或复用受保护媒体 URL。
- 只识别已核实的 CicadaPlayer 内核；不支持接口、参数异常或读回不一致时保留/恢复原值。切台后由代次、播放器身份、调优器身份共同阻止旧任务写入新播放。
- 起播优先级及首帧后加载 EPG 的策略继续保留。CCTV 原生和 M3U AVPlayer 仍独立。
- CI 本次仅构建包含现有功能的 full 包，不制作历史/无 Python 对照包。

## 验证与边界

新增原生执行测试验证配置副本、DRM/请求头保留、首帧恢复、SDK 更新 license 后恢复、未知内核/错误返回 ABI、参数拒绝、较小原值、旧内核释放。
UI 冒烟覆盖同台重复点击不重启、失败后可重选、连续点击只起播最终频道及原有功能。
模拟器使用 SDK stub，仅验证宿主行为；实际提速尚需真机日志证明。

缓冲调整只能缩短可调缓冲等待，不能保证消除日志中数秒的 VDN/媒体准备时间。固定续播延迟与选台延迟的移除是确定的代码改动，不能直接折算为整个首帧同等提速。
