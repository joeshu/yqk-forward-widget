# 原始咪咕列表研究与修复依据

研究日期：2026-10-19。对象为公开的 `http://www.52top.com.cn:678/downloads/migu.txt`、站点首页、仓库生成脚本及公开 `develop202/migu_video` 参考实现。没有执行远端程序，也没有保存或发布真实播放签名。

## 能确认的机制

- `.txt` 扩展名不影响内容：响应是 Extended M3U 频道目录，本次读取包含 117 个频道。响应带有 Last-Modified 和 ETag；本次 Last-Modified 为 `Mon, 19 Oct 2026 22:42:30 GMT`。这些信息说明文件快照可被替换，不能证明固定更新周期。
- 频道 URL 已包含咪咕 GSLB 路径及 `ProgramID`、`timestamp`、`SecurityKey`、`puData`、`ddCalcu` 等参数。播放器消费这些现成地址，无需先调用本项目的匿名 Android 取源接口。
- 抽样地址的 `puData` 为 32 字符，`ddCalcu` 为 36 字符；移除四个插入位置后，符合公开参考代码的首尾交错排列结构。不过插入字符与当前 Android 匿名实现不一致，不能认定发布方直接使用该实现。样本 URL 的 `userid` 为空，也不能据此判断生成请求是否使用其他授权上下文。
- 公开首页提供列表转换等工具链接，本轮没有找到公开的该文件生成程序或生成说明。因此，生成端如何请求上游、采用何种客户端或授权、签名寿命多长，仍未知。单独更新 URL 时间戳或重排 `puData` 不等于获得新的上游授权。
- 仓库 `update_migu.py` 不申请咪咕播放授权：它下载上述文件，校验并保留已有 URL 后发布 `migu.m3u8`。仓库 Actions 计划每小时第 17、47 分更新；计划与实际成功需要区分。

## 本项目的修复

0.5.0 默认使用仓库发布列表，获取失败、校验失败或超过本地快照年龄策略时尝试原始列表。保留签名 URL 原文；用 ProgramID 生成固定本地频道入口，后续刷新替换其目标。目录刷新合并并发请求，失败保留仍符合年龄策略的上一版。默认路径不再调用已在用户环境发生授权拒绝的匿名取源接口。

GSLB 会重定向到实际 CDN。处理相对 HLS 子清单、分片地址时必须以最终响应 URL 为基准。本轮按此解析，完成本地入口、上游清单、媒体分片、首帧解码验证。这里只解决已观察到的取源路径问题；第三方源停止更新或上游撤销签名，仍可能导致播放失败。

## 验证范围

服务器环境实测 CCTV1、CCTV2、CCTV13：本地入口 302、媒体清单 200、下载视频分片并成功解码首帧。记录见 `live-validation-0.5.0.json`，不含签名 URL。测试首个 H.264 480p 变体，不代表最高画质、全部频道、长期播放、回看或 iPhone 已验收。ffmpeg 仅用于开发验收，单文件运行不依赖它。

节目单继续使用官方当天节目接口；并未因为原列表头提供了 XML 地址就改用已经过期的镜像节目单。
