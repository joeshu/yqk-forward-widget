# 咪咕原始列表播放机制与 0.6.3 优化记录

研究对象：公开列表 `http://www.52top.com.cn:678/downloads/migu.txt`；日期：2026-10-20。

## 已验证事实

- 列表响应为 UTF-8 Extended M3U，本次 117 个频道、约 101 KB；响应带 `ETag` 和 `Last-Modified`。
- 对本次响应的 ETag 发起 `If-None-Match`，服务器返回 `304 Not Modified`。
- 每个频道 URL 是已签发的咪咕 GSLB HLS 入口，包含时间戳和校验/会话查询参数；这些值不应被项目重排、截断、记录到日志或尝试本地续签。
- 抽样入口响应为 `302`，转至咪咕 CDN 的 HTTP:8080 主清单；主清单为 HLS，使用带原查询参数的相对变体 URI。相对 URI 必须按最终 CDN 响应 URL 解析。
- 当前项目的原生 API 取源路径在既有验证中收到 `COPYRIGHT_AREA_INVALID`，不能作为默认可播放路径。

## 播放链路

`播放器 → 本地 /live/<固定频道键>.m3u8 → 302 原始已签发 GSLB URL → CDN 主清单 → 相对子清单 → 分片`。

本地固定频道键从 `ProgramID` 导出，因此源列表刷新、签名与显示名变化后，播放器订阅入口保持不变。服务默认仅重定向，不代理媒体分片；`--mode manifest` 仅获取并重写清单内相对 URI，媒体仍由播放器直接向上游 CDN 请求。

## 本地工作副本的优化

- 版本升为 0.6.3。
- 默认提供方改为 `list`：优先实时原始列表；失败、超时、过期或校验失败时回退到仓库已验证快照。
- 单文件在进程内保存同一来源的 ETag，刷新时使用 `If-None-Match`；304 仅复用仍通过完整校验的同源内存快照，不持久化签名 URL。
- 原生取源保留为显式 `--provider native` 实验功能，避免将未验播且被授权拒绝的链路作为默认行为。
- 保留列表规模、签名时间、频道保留率、URL 域名/端口和重定向边界验证；不将第三方列表变成任意 URL 代理。
- 修复 `migu/publish.sh` 的 Bash process-substitution 在 iSH 约束测试环境中的兼容性问题。

## 验证

- 上游条件请求：`304`。
- 项目回归：`tests/migu` + `tests/migu_live` 共 81 项通过。
- 单文件生成和一致性检查通过：`python3 migu/build_service.py --check`。
- 本地服务回归覆盖固定入口 302、HLS 清单相对 URI 重写、列表回退、令牌边界及发布脚本并发提交场景。

## 限制

本次不证明全部频道、全部网络/地区、iPhone 实机或长时间播放均可用；上游签名、地区和账号授权规则可能随时变化。
