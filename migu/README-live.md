# 咪咕单文件服务 0.3.0

下载 [migu-live.py](https://raw.githubusercontent.com/joeshu/yqk-forward-widget/main/migu-live.py)，Python 3.10+，仅需一个文件，无 pip、Node 或项目目录依赖。固定版本为 [migu-live-v0.3.0.py](https://raw.githubusercontent.com/joeshu/yqk-forward-widget/main/migu/migu-live-v0.3.0.py)。

```sh
python3 migu-live.py 18768
```

手机 App 直接运行时默认端口也是 18768。保持运行，在同一设备的播放器订阅：

```text
http://127.0.0.1:18768/all.m3u
```

`/migu.m3u8` 是同一目录的别名。`127.0.0.1` 指播放器所在设备；跨设备使用见下文。App 挂起脚本或关闭运行环境时，本地服务会停止。

## 节目单

订阅头自动声明本地 XMLTV 地址：

```text
http://127.0.0.1:18768/epg.xml
```

支持 `x-tvg-url` 的播放器可自动发现；其他播放器可将上面地址手动填入节目单设置。目录中的 `tvg-id` 和 XMLTV 的频道 ID 均使用稳定的 `p<咪咕频道ID>`，不依靠频道名称模糊匹配。中文、特殊字符和北京时间 `+0800` 由 XML 序列化与时区转换处理。

节目数据直接来自咪咕官方当天节目接口，**没有使用旧的 GitHub XML 镜像**：核查时那些镜像仍是 2026 年 8 月数据。每日日期按北京时间计算，跨零点会重新获取当天节目。节目预告只表示播出安排，不代表当前账号有播放权限，也不启用回看。

首次访问 `/epg.xml` 才启动后台获取，每批最多 4 个频道，首次最多等待 5 秒，然后返回当前已有的有效节目；未取得有效数据时返回 503，可稍后重试。第一轮可能需要约 1–2 分钟，期间已加载的节目可先使用。**首次导入后若节目不全，稍后在播放器里刷新节目单**；播放器是否自动重复下载由其自身设置决定。

- 有效频道数据在内存中缓存 6 小时；失败或空结果冷却 15 分钟，不反复请求所有频道。
- 每轮刷新最多 2 分钟，并发上限 4；未完成的频道会在后续请求触发的刷新中继续补齐。
- 更新中可使用尚未结束、缓存年龄不超过 36 小时的上一版节目；已过期节目不会冒充当前节目。没有有效节目时不生成占位节目。
- `/diag`、`/status` 的 `epg` 字段显示实际节目条数、已匹配频道数、缺少节目的频道、更新中状态及错误。目录共有 123 个频道，不承诺每个频道都有官方节目单。
- 节目单更新独立于直播取源，更新失败不阻断 `/all.m3u` 或直播入口。

禁用节目单：

```sh
python3 migu-live.py 18768 --no-epg
```

## 本版精简和手机运行改进

0.3.0 移除了当前单文件中的第三方列表源、旧列表解析、文件缓存、文件锁和旧回看分支。旧版本只作为历史发布记录保留；当前版本不再接受 `--source`、`--input` 等旧列表参数。静态目录更新脚本 `update_migu.py` 独立保留，不再打包进本服务。

默认仅监听 `127.0.0.1`，无需服务访问令牌、不写运行文件。频道配置内置于脚本，订阅目录不依赖外网。直播打开时才向咪咕取源；节目单在首次请求时独立加载，无周期性后台扫描。

启动日志显示版本、Python 版本、平台、主线程状态、频道数，以及订阅和诊断地址。`/diag` 保存最近 120 条脱敏诊断，重复代码 15 秒内合并；常见地区限制、网络和节目单错误带中文说明。日志不记录请求查询、访问令牌、原始接口响应或播放签名。

后台任务使用有界的守护线程与队列；停止时取消排队任务，关闭监听和仍在处理的客户端连接。已经发出的网络请求可能继续运行到其超时，但不会阻止独立进程退出；宿主 App 保留解释器时，旧请求可能短暂留在后台。信号接口不可用时不接管宿主信号，可以使用 App 的停止按钮。

## 直播行为和限制

内置 123 个频道的 ID、名称和分组。默认匿名标清 `rateType=2`；不含账号、共享 token、会员登录或设备注册流程。地区、登录、会员或接口变化的拒绝会明确报错，不尝试规避限制。

同频道同时请求合并取源，最多 4 个工作线程和 8 个进行中/排队键；成功地址缓存 30 秒，失败冷却 5 秒，最多保存 64 个结果。媒体和 API 地址限制主机、端口、路径、重定向及响应大小；保留系统代理和 TLS 校验。

| 模式 | 参数 | 行为 |
| --- | --- | --- |
| 直连，默认 | 无 | 固定频道入口返回 302，播放器访问咪咕 CDN。 |
| 清单转发 | `--mode manifest` | 读取入口 HLS，按最终响应地址展开相对 URI，保留变体、KEY/MAP 和时间线；视频由播放器访问 CDN。 |

服务不下载视频分片、不转码，也不提供无缝会话迁移；CDN 会话过期后可能需要重新打开频道。清单模式最多 4 路下载、8 个进行中/排队键，成功缓存 1 秒、失败冷却 3 秒，已完成缓存最多 32 条/8 MiB；每张清单最多 512 KiB。客户端并发上限 32。

## 诊断和局域网使用

```text
http://127.0.0.1:18768/diag
http://127.0.0.1:18768/status
```

`process_up`、频道目录和节目单就绪不代表视频已经解码；状态中的 `playback_verified: false` 明确保留这个区别。当前服务器直播取源曾返回地区限制，iPhone 实机与长时间播放尚未验收。

跨设备使用需要明确配置地址，并自动启用服务访问令牌：

```sh
python3 migu-live.py 18768 --bind 0.0.0.0 --public-base http://192.168.1.10:18768 --data-dir /可写目录/migu-live
```

日志显示 `access.token` 路径；订阅为 `http://192.168.1.10:18768/all.m3u?token=文件中的令牌`。节目单地址会自动携带同一访问令牌，节目单、状态、诊断、直播接口均受相同检查。

也可使用 `--require-token` 强制本机鉴权，或 `--token-env MIGU_ACCESS_TOKEN` 从指定环境变量读取 32–128 个 URL 安全字符。只有持久化访问令牌时需要可写目录，默认 `~/.cache/migu-live`；本机默认仍是纯内存模式。免令牌模式限制 Host 和跨站请求；对外地址不从 Host/Forwarded 头推断。公网部署应使用 HTTPS 反向代理与访问令牌。

## 开发和验证

源模块：`migu/core.py`、`migu/workers.py`、`migu/native.py`、`migu/epg.py`、`migu/service.py`。构建器将这些源码展开为可审阅单文件，并生成 SHA-256 指纹；没有动态 exec、压缩代码载荷或远程代码加载。

```sh
python3 -m unittest discover -s tests/migu -v
python3 -m unittest discover -s tests/migu_live -v
python3 migu/build_service.py --check
```

测试包括当前 HTTP 权限、节目单转换、部分更新、失败和日期切换、线程/队列上限、停止与原端口重启，以及历史发布的兼容回归。真实网络结果见 [0.3.0 验证记录](live-validation-0.3.0.json)。Linux 下的测试不能代替用户 App 的实机验证。

参考：用户提供的 [YSP v9.5](https://garysclub.sharewithyou.dpdns.org/ysp-live/ysp-live-v9.5.py) 的启动与诊断方式，以及 [develop202/migu_video](https://github.com/develop202/migu_video) 中公开的咪咕接口字段；没有执行它们的代码或复制账号/设备注册流程。节目单使用固定 HTTPS 接口 `https://program-sc.miguvideo.com/live/v2/tv-programs-data/<频道ID>/<北京时间日期>`。
