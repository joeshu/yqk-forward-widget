# 咪咕动态服务 0.1.0

下载 [migu-live-v0.1.0.py](https://raw.githubusercontent.com/joeshu/yqk-forward-widget/main/migu/migu-live-v0.1.0.py)，只需要这个 Python 文件，Python 3.10+，没有 pip 或 Node 依赖。

```sh
python3 migu-live-v0.1.0.py 18768
```

脚本保持运行，在同一台设备的播放器订阅：

```text
http://127.0.0.1:18768/all.m3u
```

端口可以更改，例如 `python3 migu-live-v0.1.0.py 9000`，对应订阅 `http://127.0.0.1:9000/all.m3u`。本机默认不要求令牌，监听范围仅限 `127.0.0.1`。`/migu.m3u8` 是同一份频道目录的别名。

`127.0.0.1` 始终指播放器所在设备。如果脚本在 NAS、播放器在手机上，请使用后面的局域网方式。关闭脚本后服务即停止。

## 两种播放方式

| 模式 | 启动参数 | 行为 |
| --- | --- | --- |
| 直连，默认 | 无需额外参数 | 固定频道入口返回 302，播放器直接访问当前上游地址；服务不消耗视频转发带宽。 |
| 清单转发 | `--mode manifest` | 服务读取入口 HLS，按重定向后的最终地址改写子清单、音轨、字幕、KEY/MAP 等相对 URI；保持所有变体和原始时间线，视频仍由播放器访问 CDN。 |

```sh
python3 migu-live-v0.1.0.py 18768 --mode manifest
```

订阅地址保持 `/all.m3u`。清单模式适用于播放器对入口 302 或相对地址兼容不好时。两种模式均不下载、缓存或转发视频分片，不重新封装视频，不固定最高码率，不提供央视频 4K 设备协议。

服务从原有咪咕列表读取真实播放地址，使用节目 ProgramID 生成稳定频道路径；无 ProgramID 时使用规范化频道 ID 的摘要。签名、显示名称变化通常不改变 ProgramID 频道入口。

## 刷新与故障处理

- 首次订阅时加载列表；首次最多等待 5 秒，仍在加载则返回 503 和 Retry-After，可稍后重试。默认 60 秒内共用同一目录，过期后的访问合并为一次后台刷新，多个频道不分别下载整份列表。
- 刷新期间可继续使用满足绝对签名时间策略的上一版。失败冷却从 5 秒递增到最多 60 秒；无观看/订阅请求时不定时扫描上游所有频道。读取 `/status` 不触发外部播放探测。
- 沿用项目的 UTF-8、域名/端口、重定向、签名时间、至少 100 频道及 90% 原频道 ID 保留校验。更新不合格时不发布候选。默认 12 小时只是本地发布/缓存年龄上限，**不是令牌真实有效期**。
- 支持 ETag/Last-Modified；304 仍检查绝对签名年龄，无变化时不重写缓存。运行数据默认位于当前目录 `migu-live-data/`，目录和来源缓存按私有权限创建；请勿提交该目录。
- 清单模式共享相同 URL 的并发下载，最多 4 路下载、8 个进行中/排队键；成功缓存 1 秒，失败冷却 3 秒，已完成内容最多 32 条/8 MiB。进行中响应和客户端连接另有内存开销。每个上游清单最多 512 KiB。
- 客户端并发最多 32 个，客户端 socket 超时 10 秒；取源使用有界超时/重试，媒体清单不对 403/661 反复重试，不换设备、不注册帐号。Ctrl+C/SIGTERM 停止服务；在途下载结束前，Python 可能仍有短暂退出等待。

## 状态与回看

```text
http://127.0.0.1:18768/health
http://127.0.0.1:18768/status
```

返回 JSON：进程存活、目录就绪、频道数量、是否刷新中、最近取源时间和脱敏错误。`playback_verified: false` 表示没有据此验证实际视频解码；目录就绪不代表所有频道实播成功。

上游附带已知回看模板时保留回看入口。服务只接受成对的 `playbackbegin/playbackend`（北京时间 14 位数字），单次最多 24 小时、开始时间在最近 7 天内；这是本地请求约束，不代表上游提供 7 天回看或每个频道都支持。匿名本机路径的模板使用 `?`，令牌路径使用 `&`，避免错误拼接。

## 局域网或反向代理

开放到非本机监听时，必须提供固定对外地址，并自动启用访问令牌：

```sh
python3 migu-live-v0.1.0.py 18768 --bind 0.0.0.0 --public-base http://192.168.1.10:18768
```

首次生成 `migu-live-data/access.token`，订阅为：

```text
http://192.168.1.10:18768/all.m3u?token=文件中的令牌
```

状态和频道接口也需要令牌。可以用 `--require-token` 强制本机鉴权；或用 `--token-env MIGU_ACCESS_TOKEN` 从指定环境变量读取，要求 32–128 个 URL 安全字符，该方式不将令牌写入文件。日志不打印真实令牌，默认访问日志关闭。播放器下载的受保护目录包含服务访问令牌，请妥善保存。

公网使用应部署 HTTPS 反向代理，`--public-base https://tv.example.com` 会自动要求令牌；URL 不从客户端 Host/X-Forwarded 头推断。免令牌模式还限制 Host 和跨站浏览器请求，降低 DNS 重绑定风险。不要将免令牌本机服务直接转发到公网。

## 运行范围和限制

这里的动态入口刷新的是第三方目录快照，不重新生成咪咕鉴权。原上游 HTTP、地区/IP 条件、其自身更新周期和实际签名有效期仍然生效。

302 和清单模式都会把上游资源 URL 交给已连接的播放器，不能隐藏全部鉴权信息。频道打开后，播放器可能直接持续请求 CDN 子清单，服务不能在这种连接中替播放器无缝切换已过期会话；重新打开频道才会再次经过固定入口。真正的全链路代理、分片缓存和会话迁移不在此版本范围内。

节目单和台标沿用目录已有地址。未在本地恢复第三方 HTTP 内容的真实性，也不能把服务端 HTTPS 等同于上游端到端 HTTPS。
