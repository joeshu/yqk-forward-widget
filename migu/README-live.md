# 咪咕单文件服务 0.8.4

下载 [migu-live-v0.8.4.py](https://raw.githubusercontent.com/joeshu/yqk-forward-widget/main/migu/migu-live-v0.8.4.py)，或更新根目录 [migu-live.py](https://raw.githubusercontent.com/joeshu/yqk-forward-widget/main/migu-live.py)。Python 3.10+，标准库，无 pip、Node、浏览器或项目目录依赖。

**默认直接按公开参考项目的取源分支请求咪咕，不读取外部播放列表，也不会在取源失败时自动切换列表。** 用户已反馈 iOS 可播，0.8.4 针对快速切台的排队及临时失败恢复进行优化。此前 0.8.1 服务器的地区拒绝仅代表当时服务器环境，记录见 [live-validation-0.8.1.json](live-validation-0.8.1.json)。

```sh
python3 migu-live.py 18768
```

手机 App 直接运行同样默认端口 18768。日志应显示 `0.8.4`、`provider=migu-android`。保持脚本运行，在同一设备播放器订阅：

```text
http://127.0.0.1:18768/all.m3u
```

`/migu.m3u8` 是目录别名。App 挂起或停止 Python 时，本地服务也会停止。

0.8.1 继续对照参考项目的 `utils/net.js`、`account.js`：API 请求补齐其默认 `User-Agent: node-fetch` 和 `Accept: */*`。仍请求 identity 编码，保留本地响应大小与解码边界；不轮换请求头或客户端试探放行。账号与实际画质只从正常播放响应观测，不额外轮询上游。

0.8.2 新增独立的参考代码对照：固定时间、随机数与合成响应，实际执行经哈希核对的参考 JavaScript 函数，比较生成的请求与播放地址。发现并修复账号请求高清却收到游客标清时的补签差异：校验沿用请求模式，返回画质仅用于观测。5 个场景的请求、模块请求头及播放地址均与参考输出一致，见 [对照记录](reference-comparison-0.8.2.json)。这不是实际账号或真实媒体播放验收，不能解决 API 返回地区拒绝的问题。

## 与参考项目对齐的取源规则

本轮阅读 [akiralereal/iptv 的 migu 模块](https://github.com/akiralereal/iptv/tree/e475b2f6d24029f844ada2b362d703c8b88c2e9b/extractors/migu)，未启动其服务器、登录流程或安装脚本。代码协议参考该项目，保留本地有界线程、系统代理、TLS 校验、固定媒体域名及有限请求预算。参考项目的存在不代表同一接口在所有网络均能播放。

- 未登录且请求档位 ≥3：按 `resolve.js` 走 `2600034600` 旧版高清请求，实际请求档位 3、随机盐值，以 `25` 结尾；不发送账号头。
- 请求档位 2，或登录后请求更高档位：走现代接口，请求头 `AppVersion=2600037000`，签名版本取前 8 位 `26000370`。档位 2 不发送账号头。
- 只有明确会员档位拒绝时才请求更低档位，不重复同档、不升级尝试；最多三次请求共享 12 秒总预算。地区、版权、终端拒绝不轮换客户端或网络重试。
- 完整签名地址原文返回，不重复追加 `ddCalcu`。待补签地址检查种子、签发时间、频道 ID 及既有 `sv/ct` 后缀；保留原查询编码与顺序。
- 奇数长度种子中间字符只保留一次，签名日期从已签发 URL 读取。此项是对参考代码边界情况的修正，不声称逐字复制其所有行为。
- 正常返回的游客/降档地址可能伴随账号认证未通过；只凭 `authResult=FAIL` 不判断必需会员。接口明确拒绝、缺少地址、频道不符或格式异常仍失败，不把 HTML、302 或地址存在等同于视频可播。

原列表的 `2600000900` 数字映射规则与这里的 `2600034600`/现代规则不同。不能只把 `MIGU_APP_VERSION` 换成 `2600000900`，仍使用另一版本的签名常量。本版会拒绝该混用；显式旧版实验模式见下文。更多依据见 [reference-parity-0.8.0.md](reference-parity-0.8.0.md)。

## 单文件顶部配置

默认提供方使用文件最上方的 `ANDROID_OPTIONS`。可编辑自己的 `user_id`、`token`、`rate_type`、HDR/H265 开关；更改后重启。环境变量优先：

```sh
MIGU_USER_ID=你的账号ID MIGU_USER_TOKEN=你的令牌 MIGU_RATE_TYPE=3 \
python3 migu-live.py 18768
```

没有账号也可启动并发起参考项目的游客请求，上游决定是否授权及实际画质。`MIGU_RATE_TYPE` 支持 2/3/4/7/8/9。默认不额外请求投屏专用档位，不自动注册设备、登录或刷新账号令牌。`MIGU_HDR=0`、`MIGU_H265=0` 可关闭对应请求参数。

凭据只进入固定咪咕 HTTPS API 的请求头，不进入本地订阅、状态或诊断；账号对象不输出令牌。填写后的本地脚本不要提交到公开仓库。协议常量不等于账号权限，未知客户端的新签名流程仍需修改适配代码，不能保证仅换一项配置就恢复。

`NATIVE_SETTINGS` 仅供 `--provider native` 的早期 `2600000900` 实验路径使用；它不控制默认 Android 模式。旧版模式没有当前环境成功播放证明，不自动轮换标识或忽略错误。`MIGU_APP_VERSION`、`MIGU_CLIENT_CHANNEL_ID`、`MIGU_APP_CODE` 应与所选模式配套，勿将旧版标识混入现代算法。

默认将 GSLB 地址交给观看设备，由观看设备选择 CDN，不在服务器预先固定 CDN 节点。不支持服务端节点解析开关，设置 `MIGU_CLIENT_DISPATCH=0` 会明确报错，避免此前选项存在但未生效的问题。

## 明确选择其他提供方

```sh
python3 migu-live.py 18768 --provider native
python3 migu-live.py 18768 --provider list
```

原生及 Android 模式都使用内置 123 个频道，目录无需联网即可生成。列表模式是显式选项，优先下载实时原始列表，失败或校验不合格时尝试仓库快照；支持同源 ETag 条件刷新，不保存签名 URL 到磁盘。默认模式不执行这些列表请求。

## 0.8.4：快速切台

- 同时最多 8 路解析，另有最多 8 个等待位；较新的待处理请求优先，避免第 9 个频道在忙碌时立即失败。总真实出站并发仍不超过 8。
- 同频道仍共享一次取源。一个等待者超时不会取消其他等待者的请求；只有本地等待超时、没有其他等待者且尚未开始的任务才取消。HTTP 请求本身没有“当前选台”标记，不会全局取消其他正在运行的频道。
- 临时网络、预算超时和服务端临时错误冷却 3 秒；版权、地区、登录和会员拒绝保持 60 秒冷却，不主动循环重试。
- 取消任务与本地限流不写入频道失败缓存。新解析额度在任务真正开始时计入，排队和取消不消耗额度。
- `/status`、`/diag` 增加 `active_resolves`、`pending_resolves`、`transient_failure_seconds`，可结合慢取源记录判断拥堵。

这些变化通过合成并发与 HTTP 测试验证，用户设备快速切台的改善幅度仍需实际比较。已发出的上游请求继续受原有超时约束，不强行杀线程。签名、画质、节目单与媒体直连路径沿用上一版，没有增加全频道预热或播放器缓冲。

## 0.8.3：开播和切台等待观测

用户设备已反馈 0.8.2 可播。本轮日志只有启动、一次网络错误、一个频道版权屏蔽和一次解析限流，没有成功请求耗时，也没有播放器缓冲或画面时间戳，因此不能据此计算开播或直播落后秒数。此前服务器的地区拒绝不能用于否定用户设备的成功播放。

保留每分钟 30 次新解析与 8 路并发上限。限流时 `Retry-After` 改为滚动窗口实际剩余秒数（1–60），不再固定 60；若播放器遵守该响应头，可减少多等的时间，并非提高请求频率。缓存命中不消耗新解析额度，也不额外发请求。

`/status`、`/diag` 新增 `recent_resolves`，最多保留 32 次本地取源的频道 ID、耗时和结果；不保存播放地址或账号。超过 1 秒的取源等待会在宿主日志打印 `MIGU_SLOW_RESOLVE`，成功和失败都可观测。耗时包含本地等待及取源，**不含播放器访问 CDN、下载分片和缓冲时间**。网络错误日志补充已知频道 ID，不改变错误响应正文。

如果慢在第一次开播/切台，先看这些耗时与是否发生 429；如果画面一直落后实际直播，则需看 HLS 分片及播放器直播缓冲，本次未擅自改动播放器缓冲、转码或视频分片。

## 性能与稳定性

所有真实出站请求共用 **8 路总并发**，各工作池不会叠加成 24 路连接；排队时间计入请求预算。后台线程、队列、HTTP 客户端数量和响应大小均有上限。系统 DNS 解析不能被 Python 强制中止，调用方等待仍受截止时间限制。

默认取源同频道合并请求，成功地址最多缓存 5 分钟、临时失败冷却 3 秒、明确权限/版权等拒绝冷却 1 分钟，最多 64 条；5 分钟是本地缓存策略，不是已证明的签名有效期。60 秒内最多发起 30 次新解析，缓存命中不计入；过密返回 429 与按窗口剩余时间计算的 Retry-After，避免批量扫描打满上游。明确地区、终端、版权或权限拒绝返回 403。

`--mode manifest` 可转发 HLS 清单，并按最终响应 URL 展开相对路径；媒体分片由播放器直接下载。默认只返回 302，不下载分片、不转码。媒体地址不自动添加未知域名白名单；跳转到 `bofang.miguvideo.net.cn` 不能在未取到 HLS 和分片时认定为正常媒体调度，更不能直接归因于 DNS。

## 节目单与重启缓存

订阅自动声明 `http://127.0.0.1:18768/epg.xml`。不支持自动发现的播放器可手动填入。XMLTV 使用稳定的 `p<频道ID>` 与目录对应；节目单就绪不表示频道有播放权限。

节目来自固定的咪咕官方当天节目接口，日期按北京时间计算；没有改回旧的 GitHub XML 镜像。首次请求才后台获取，每批最多 8 个频道、每轮最多 2 分钟。首次等待最多 5 秒，可返回已加载的部分节目；无有效节目时返回 503，稍后刷新。

成功数据缓存 6 小时；缺失/失败频道按 15 分钟、30 分钟、1 小时逐级退避，最长 6 小时。跨北京时间零点重新取当天节目。节目单失败独立于频道目录和播放入口。

```sh
python3 migu-live.py 18768 --epg-cache
```

默认纯内存。此选项将有效节目及重试状态原子保存到 `~/.cache/migu-live/epg-cache-v1.json`，可配合 `--data-dir` 指定可写目录；不保存签名 URL 或账号。损坏、过期、符号链接或不可写缓存退回内存，不阻止启动。禁用节目单用 `--no-epg`。

## 诊断与局域网

访问 `/status` 或 `/diag` 查看当前版本、提供方、`request_profile`、节目单进度和脱敏错误。`playback_verified: false` 表示没有据此完成视频解码验收。

`credential_state` 区分未配置、未检查、未发送账号、上游认可、上游不认可及未知。只有实际发送了账号的响应才用于判断是否被认可；请求标清时不发送账号，不能将游客响应误报为令牌失效。`upstream_observation` 提供脱敏的 `account_sent`、`logged_in`、`requested_quality`、`actual_quality`、`trial_seconds`、接口 code/rid 及是否有地址。实际档位与配置档位可能不同，试看时长为空表示上游未提供，不等于无限制播放。上游不认可登录不直接判定令牌过期原因。以上信息不含账号、令牌、签名或原始 URL。

默认仅监听 `127.0.0.1`，无需服务访问令牌。跨设备需显式配置地址并自动启用令牌：

```sh
python3 migu-live.py 18768 --bind 0.0.0.0 --public-base http://192.168.1.10:18768 --data-dir /可写目录/migu-live
```

订阅增加 `?token=文件中的令牌`，节目单自动携带同一令牌。可用 `--token-env MIGU_ACCESS_TOKEN` 提供服务令牌；该令牌与咪咕账号授权不同。权限、Host/Origin 检查保持；公网使用 HTTPS 反向代理。
